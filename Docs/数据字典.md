# 数据字典：数据库配置与内存运行态

运行态及展示字段核对更新：2026-10-16。数据库映射以 [AppDbContext](../src/AutomatedLine.Infrastructure/Persistence/AppDbContext.cs) 为准，字段以两个 EF 实体为准；本文不假定数据库自动创建或迁移。

## 1. CraneConfig 表

实体：[CraneConfig](../src/AutomatedLine.Infrastructure/Persistence/Entities/CraneConfig.cs)。Id 为人工提供主键，EF ValueGeneratedNever；No 有唯一索引。double/int/bool 等存储类型由 EF/MySQL 映射，运行字段不在此表。

| 字段 | CLR/长度约束 | 默认/作用 |
|---|---|---|
| Id | int，主键 | 天车号，驱动/通道/工件位置关联键 |
| No | int，唯一索引 | 显示序号，可不同于 Id |
| Name | string，必填，最长50 | 名称；默认空字符串 |
| Protocol | string，必填，最长30 | 兼容保留；当前 DriverFactory 不使用其值 |
| IpAddress | string，必填，最长50 | 实际 PLC IP |
| Port | int | 兼容保留；天车实际固定502/站号1 |
| StartX / EndX | double | X覆盖范围，边界包含 |
| Width | double | 路权外扩半宽 |
| SafeX / SafeZ | double | 正常收尾绝对目标，不额外加车偏移 |
| OffsetX / OffsetY / OffsetZ | double，默认0 | 加到设备XYZ基础坐标 |
| SpeedX / SpeedY / SpeedZ | double | 自动执行前转成驱动速度写值 |
| AccelX / AccelY / AccelZ | double | 三轴加速度 |
| DecelX / DecelY / DecelZ | double | 三轴减速度 |
| IsEnabled | bool，默认true | 装载与参与选车 |
| Remark | string?，最长200 | 可空；当前页面DTO不编辑 |
| UpdatedAt | DateTime，初始UTC当前时间 | 配置保存时更新UTC；当前页面不展示 |

除显式默认项外，数值 CLR 默认0。MoveTimeoutMs 不在配置表；运动超时和容差来自 App.Crane。

## 2. DeviceConfig 表

实体：[DeviceConfig](../src/AutomatedLine.Infrastructure/Persistence/Entities/DeviceConfig.cs)。Id 为人工填写主键，EF ValueGeneratedNever。DeviceType 字符串转换，长度30。

| 字段 | CLR/长度约束 | 默认/作用 |
|---|---|---|
| Id | int，主键 | 设备号，位置/预约/驱动/斜床参数关联键 |
| Name | string，必填，最长50 | 页面与日志名称 |
| DeviceType | DeviceType，字符串存储 | 默认Unknown；决定工序、驱动和handler |
| Protocol | string，必填，最长30 | 保留配置，当前工厂忽略 |
| IpAddress | string，必填，最长50 | 实际连接IP |
| Port | int | 保留配置；实际端口按设备类型固定 |
| PositionX / PositionY / PositionZ | double | XYZ物理基础坐标；Domain设备持有X，上下文另取Y/Z |
| MinDiameter / MaxDiameter | double | 候选目标直径闭区间 |
| MinLength / MaxLength | double | 候选目标长度闭区间 |
| IsEnabled | bool，默认true | 决定装载及工序参与 |
| Remark | string?，最长200 | 可空，页面DTO不编辑 |
| UpdatedAt | DateTime | 初始/保存UTC时间，页面不展示 |

实体没有自动归一化最小/最大值，也没有数据库工艺路线表。运行端口、站号详见[通信说明](通信与点位说明.md)。

## 3. 工件信息：仅内存

源码：[WorkpieceInfo](../src/AutomatedLine.Domain/Workpieces/WorkpieceInfo.cs)。Info 为整体替换的数据对象，编辑保留 RuntimeId。

| 字段 | 类型 | 使用位置 |
|---|---|---|
| RuntimeId | Guid，自动生成 | 工件身份，区别于每段TransportTask.TaskId |
| PlateNo / SerialNo | string / int | 板号、序号，ToString为板号/序号 |
| Length / Diameter | double | 设备能力筛选、运动目标及加工原值；双头镗301长度舍入、303外径×10后舍入，界面原值不变 |
| PlugThickness | double | 统一堵厚原始值；双头镗309下发时Convert.ToInt32后转Word |
| PlugHole | int | 70/100，斜床堵孔和偏移、研磨模式、打号内径 |
| PrintContent | string | 打号机UTF-8内容 |
| LatheMachiningMode | int，默认1 | 斜床#909，UI输入1～10 |

UI校验：板号非空、序号非负整数（>=0）、直径/长度正数、堵孔70/100、斜床工艺1～10。不是EF约束，不意味着其他调用者自动受这些校验；人工添加不强制板号/序号唯一，仍创建Created任务。ERP专用TryAddImportedBatch在同一锁内对现有和批内版号/序号去重，重复项不覆盖原任务，成功项按文件行序自动启动为Waiting并分配递增QueueOrder，详见[ERP接收说明](ERP文件接收说明.md)。

## 4. 工件运行态：仅内存

| 字段 | 初始值 | 含义 |
|---|---|---|
| TaskState | Created | 生命周期，与位置独立 |
| CurrentLocation | Queue | Kind + 可空ResourceId；设备/车位置必须带资源号 |
| CurrentProcess | Unknown | 放料成功后更新 |
| QueueOrder | 0 | 启动时分配的递增序号；人工暂停清0；不是UI连续排位 |
| ProcessPlan | null | 首次启动锁定的不可变ProcessPlanSnapshot，有序Nodes、路线Version与Description；只绑定一次，暂停恢复和故障回滚不改 |

状态和当前工序使用线程可见读写；派发Waiting→Assigned与人工暂停Waiting→Paused复用TryTransition的CAS，二者只能一方成功。暂停失败不清QueueOrder；成功才清0，再次启动分配新序号。集合快照仍引用同一批对象，不是数据库事务。

## 5. 枚举实际数值

| 数值 | DeviceType | ProcessType |
|---:|---|---|
| 0 | Unknown | Unknown |
| 1 | LoadRack | Loading |
| 2 | ForkMachine | Forking |
| 3 | BoringMachine | Boring |
| 4 | LatheMachine | Lathing |
| 5 | GrinderMachine | Grinding |
| 6 | BalancingMachine | Balancing |
| 7 | MarkerMachine | Marking |
| 8 | CheckMachine | Checking |
| 9 | UnloadRack | Unloading |

默认顺序目录不含Forking。App.processPlan.enabledProcesses是ProcessType→bool字典，缺少加工工序项默认true；上下料固定。新工件在首次启动时按开关、启用设备存在性及执行策略支持捕获路线，联网与握手不影响勾选。动平衡/验点尚未实现，灰显且不能进入新路线。已启动工件只按自身ProcessPlan找下一项，不能因设备离线、停用或移除而跳过；缺快照或当前工序不合法时等待处理。

| 枚举 | 值 |
|---|---|
| WorkpieceState | Waiting0、Assigned1、Running2、Completed3、Discarded4、Created5、Paused6 |
| WorkpieceLocationKind | Queue0、Device1、Crane2、Discarded4；3未使用 |
| CraneState | Idle0、Reserved1、Running2 |
| LineState | Stopped0、Starting1、Running2、PauseRequested3、Paused4、PausedByFault5 |
| ResourceState | Available0、Reserved1、Busy2、Alarm3、Disconnected4、BlockedByPhysicalState5 |

LineState的Starting/PauseRequested当前服务不主动设置。ResourceState用于派生展示，当前不建立BlockedByPhysicalState隔离；不存在删除工件专用Deleted状态。

## 6. 其他内存数据

TransportTask包含TaskId、WorkpieceRuntimeId、源/目标设备号和X、目标工序、优先级。CraneRuntime包含State、CurrentTask、CurrentStep、LockedInterval。SignalSnapshot保存点名值、采集时间、序号、连接与质量，挂在DeviceBase.Signals上。

| CraneRuntime字段 | 数据类型/作用 |
|---|---|
| State | CraneState，volatile后备字段，当前执行状态 |
| CurrentTask | TransportTask可空引用，volatile后备字段，当前搬运归属 |
| CurrentStep | string可空，volatile后备字段，仅保存Application最近发布的展示步骤；初始化/原步骤日志/有板检查时更新，清CurrentTask时清空，不参与调度和成功失败判断 |
| LockedInterval | XInterval?，当前实际取得的路权区间；调整成功后同步展示，非PLC位置反馈 |

大屏的[CardSignal](../src/AutomatedLine.Ui/ViewModels/CardSignal.cs)是UI展示记录，Name为中文名称，Value为bool?：true显示“● 1”、false显示“○ 0”、null显示“未知”。它不写回SignalSnapshot或PLC。设备卡片只认连接且Quality=Good快照中的真实bool值；下料架“允许放料”反转缓存HasMaterial，null仍为null。天车卡片从有效CraneStatusDto取得可空X信号，快照不可用时全部标签未知。

任务工件身份按TransportTask.WorkpieceRuntimeId关联RuntimeTaskManager；这与crane.CurrentWorkpiece表示的内存持板、CraneStatusDto.HasPlate表示的X11反馈是三个不同含义。卡片的显示文本和预约天车名称均为派生数据，不增加数据库字段。详见[大屏展示说明](页面布局/大屏展示页面.md)。

天车PLC状态单独保存在Application的CraneStateStore，不在CraneConfig、DeviceConfig、DeviceBase或CraneRuntime里。设备号与天车号各有自己的注册表和驱动字典，相同数字不互相覆盖。详细数据见[天车采集设计](天车状态采集设计.md)。

| 天车快照字段 | 含义 |
|---|---|
| CraneId / Sequence | 天车Id、全线递增结果序号；发布失败结果也递增 |
| ReadStartedAt / CollectedAt | 本轮读取开始与发布时间，DateTimeOffset；时效另外用单调时间戳计算 |
| Status | CraneStatusDto；坐标、编码器、速度、回原点、报警和X信号；整次失败null，单线圈未知可为null |
| FailureReason | 整次读取失败说明；成功状态为null，不单列每个线圈失败原因 |

缓存条目另外记录来源驱动和StartedTimestamp，用于拒绝旧驱动及从读取开始计龄。GetSnapshot返回当前驱动最近结果，不检查年龄；GetFreshStatus才过滤失败/过期等不可用情况。

ActiveAlarm实际保存Id、LastAt、Level、Source、Message、SystemAction、ResourceId、ResourceIsCrane、Count；只有最近发生时间LastAt，没有独立首次发生时间字段。活动列表按等级+来源+内容合并并更新时间/次数；弹窗没有单独的次数或等级栏。

删除工件从列表移除并清身份一致的设备/车引用；不会删对应DeviceConfig行，也不会改PLC信号。异常Discarded保留列表记录，人工删除才消失。

## 7. 配置变更

页面保存按Id更新/插入，更新时间UTC。编辑Id不自动删旧行。配置装载只取启用行；主页面“启动线路”不重新装载。管理页保存/删除会重装注册表，但不重建全部执行循环与运行态。

配置变更与重启步骤见[配置与运行说明](配置与运行说明.md)。不要把表中的Protocol/Port改动当作实际协议切换。
