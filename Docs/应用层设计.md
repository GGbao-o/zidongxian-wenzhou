# 应用层设计：当前执行逻辑

核对日期：2026-10-13。本文按实际方法调用顺序描述；配置、地址及页面展示分别见[配置说明](配置与运行说明.md)、[通信文档](通信与点位说明.md)、[页面说明](页面布局/README.md)。

## 1. 从工件到搬运任务

人工添加或ERP文件接收工件进入 Created；人工启动进入 Waiting。设备采集持续更新信号，生成器为符合条件的 Waiting 工件建立候选，调度器选车并写通道，Worker 领取后执行状态机。正常完成一段搬运后，工件回 Waiting 等下一设备请求；下料结束为 Completed。

ERP监听由宿主单例ErpImportService管理，默认暂停；主页面按钮开启持续读取，再次点击暂停后续批次。八列文件一次整批读取/解析为原始WorkpieceInfo，通过RuntimeTaskManager.TryAddImportedBatch在同一锁内检查现有及批内版号/序号后创建未启动任务，有新增时全批只发一次Changed，避免几十行逐件清空重建UI。成功行删除、失败行保留，清理失败保留本进程回执供重试；不调用Start、不改变线路/调度/状态机。详见[ERP文件接收说明](ERP文件接收说明.md)。

`WorkpieceTask` 是贯穿工艺的工件记录；`TransportTask` 是单次搬运，两个对象的 GUID 不同。运行数据不持久化。

## 2. DeviceStateCollector：设备采集

源码：[DeviceStateCollector](../src/AutomatedLine.Application/Collection/DeviceStateCollector.cs)。

1. 启动时读取 DeviceIntervalMs，默认 500ms，最低 50ms。
2. 对注册表中有 IDeviceDriver 的设备并发启动 ReadAllSignalsAsync。
3. 等本轮所有读取结束后发布各设备 SignalSnapshot，更新序号、采集时间、连接状态与质量。
4. 任一设备失败会得到断开/Bad/空点表；记录日志，然后后续轮次继续读取。

同一 Modbus 设备内部逐点请求，不是整张表一次批量读。慢设备会延迟本轮其他设备快照发布。线路暂停不暂停采集。

驱动总注册表同时保存设备与天车，但本采集器使用 `OfType<IDeviceDriver>()` 过滤，只将地面设备结果按DeviceId写入DeviceBase.Signals；天车不继承DeviceBase，也不使用此缓存。找不到设备对象时跳过，通信读取失败则给已有设备写断开空快照。

天车由独立的 CraneStateCollector 后台采集，发布到 Application 的 CraneStateStore，四处通过只读 ICraneStateProvider 消费；运动和动作确认仍即时读取。

### 2.1 CraneStateCollector：天车共享采集

每车一个串行循环，读完立即发布，再等 CraneIntervalMs（默认500ms），跨车不等待。失败替换为不可用结果，循环继续；首轮与失败/恢复记录日志，连续结果抽样。缓存从读取开始以单调时钟计龄，默认最大2000ms，校时不改变期限；驱动更换、停用、未采集、失败或过期均不返回有效状态。宿主停止取消并观察所有循环。

大屏与手动页只读缓存；调度使用有效缓存选车；冷启动并发有界等待有效且X11已知的缓存，超时只记录核对未完成，保持原仅提示策略。完整职责、配置、重载与日志见[天车状态采集设计](天车状态采集设计.md)。

Publish整体更新CraneStateStore内部按CraneId索引的ConcurrentDictionary；读写服务经DI共用同一单例。GetSnapshot用于查看当前驱动最近结果和失败原因，不保证未过期；四处消费者用GetFreshStatus过滤时效。后台发布不直接修改页面属性，两个页面各自每1s取缓存、赋绑定属性，由PropertyChanged显示新值；采集等待500ms与UI节拍是不同设置。

## 3. TransportTaskGenerator：候选任务生成

源码：[TransportTaskGenerator](../src/AutomatedLine.Application/Generation/TransportTaskGenerator.cs)、[DeviceHandshakeRules](../src/AutomatedLine.Application/Generation/DeviceHandshakeRules.cs)。

### 3.1 线路和工件前提

只有线路 Running 才重算候选；其他状态清候选池。只处理 TaskState=Waiting，因此人工暂停后的 Paused 工件不会继续生成候选。

单工件暂停与调度派发使用同一个原子状态迁移：`Waiting→Paused` 和 `Waiting→Assigned` 只能有一方成功。派发先成功时，暂停返回失败并保留 QueueOrder；暂停先成功才清排位，再次启动仍重新入队尾。

队列来源只认 Location=Queue 且 Waiting 的最小 QueueOrder 工件。选择第一个启用上料架，要求已连接、未预约、HasMaterial=true。后面的板不会越过队头，即使尺寸更适合另一设备。

设备来源要求工件 Location 指向该设备、设备启用、CurrentWorkpiece 与工件为同一对象、连接正常、未预约、无已实现报警且满足取料信号。Discarded 不参与生成。

### 3.2 下一工序和目标

Unknown 当前工序按 Loading 起算。沿固定 ProcessRoute 找下一项有启用设备的工序。没有下一项则直接 Completed；不是自动补一次下料任务。

目标过滤：对应下一工序类型、启用、不同于源、已连接、未预约、尺寸在闭区间范围内、无设备报警、满足放料握手。**当前没有另外判断目标 CurrentWorkpiece=null。**

每个目标对应一个候选，Priority 当前均为 100，候选池整体替换。候选生成不占路权和设备预约，也不把工件置 Assigned。

### 3.3 类型判据

| 类型 | 可提供工件 | 可接收工件 | 当前报警判据 |
|---|---|---|---|
| 上料架 | HasMaterial=true | 不作为常规目标 | 无 |
| 双头镗 | RequestUnload=true | RequestData=true | 无独立报警点 |
| 斜床 | RequestUnload=true | RequestData=true | 无独立报警点 |
| 研磨机 | 有效AutoMode=1且RequestUnload=true | 有效AutoMode=1且RequestData=true | RunState=2 |
| 打号机 | ProcessDone=true | 有快照且 Busy=false | 无 |
| 下料架 | 不作为常规源 | 有快照且 HasMaterial=false（DI3/10003/PDU2原始1经驱动反转） | 无 |
| 其余类型 | 无已实现规则 | 无已实现规则 | 无 |

研磨机AutoMode来自FC03/PDU12063的原始Word，只有数值严格等于1才允许；0、其他值、缺点、未采集、断开或质量不良均不就绪。模式不满足在generation日志中注明12063原值或未知，不冒充RequestData/RequestUnload未就绪；工件继续Waiting，线路不暂停。

握手规则的 GetBool 在缺失或非布尔值时返回 false；生成器还会检查 IsConnected。执行阶段 WaitDeviceAsync 另要求点名存在且布尔值确实匹配，不把缺点当成期望 false。

工序参与只看启用配置。启用动平衡/验点但没有驱动并不会跳过它们，应按实际已实现设备配置路线。

## 4. CraneScheduler：集中式选车

源码：[CraneScheduler](../src/AutomatedLine.Application/Scheduling/CraneScheduler.cs)。

候选池为空，本轮直接返回，后台采集继续。非空时 `ReadIdleCraneStatuses` 对启用且 IsIdle 的天车查询 `ICraneStateProvider.GetFreshStatus`，保存到本轮字典；选车时 HasAlarm 和坐标来自有效共享快照，不再在调度线程读取PLC。

HasAlarm 为 D5011、D5012、D5013 任一非零。未采集、驱动身份不符、失败、过期或有报警均排除该车。本轮缓存状态供多个候选复用；日志说明状态不可用（未采集/失败/过期）。

候选先按 Priority 降序，再按最近可执行车到源 X 的距离排序。对单个候选，天车须启用、Idle 且无当前任务、覆盖源/目标 X、状态有效且无报警；再按距离源 X 最近排序。没有负载均衡或额外 HasPlate 过滤。

逐车尝试：

1. 检查对应任务区间 CanAcquire、源/目标是否已预约；都是预检查。
2. 根据候选创建 TransportTask，包含独立 TaskId 和工件 RuntimeId。
3. 读取源/目标研磨机当前有效模式缓存，复核AutoMode=1；阻塞则记录scheduling具体原因，结束本候选本轮尝试，保持Waiting，不占资源、不弃板。这样旧候选不会绕过已采集到的模式变化；不在这里额外读PLC。
4. CAS 将工件 Waiting 改 Assigned，失败则停止本候选尝试。
5. TryWrite 车通道；成功结束该候选尝试。
6. 通道写入失败将工件退回 Waiting，继续尝试其他车。

模式核对与PLC切换不是原子操作，依据最新已发布的缓存；模式后来变化不自动中止已派发或正在执行的搬运，原状态机流程保持。

Runtime.CurrentTask 和 State=Reserved 由 Worker 领取时设置。通道容量 1 限制待执行队列，不代表调度器在写入前已经拿资源。资源竞争最终由状态机再次原子获取解决。

## 5. Worker、通道和上下文

### 5.1 CraneWorker

源码：[CraneWorker](../src/AutomatedLine.Application/Workers/CraneWorker.cs)。每车一个循环，串行执行；线路非 Running 时不领新任务。线路暂停时已领取的当前任务继续执行，队列中的 Assigned 任务保留到后续恢复。

普通流程异常由状态机处理，不逃出车循环；真正宿主取消清理后重抛。循环只在 StartAsync 建立，没有运行期自动重建。点击线路启动只改变线路状态。

Worker 每次领取搬运创建独立的 [CraneTaskExecution](../src/AutomatedLine.Application/Workers/CraneTaskExecution.cs)，令牌与宿主令牌关联。人工中止通过 `TryAbortCurrentTask(craneId, expectedTaskId)` 校验当前执行归属，拒绝空闲、重复和过期任务 ID；先故障暂停线路，再取消本次令牌，不取消 Worker 宿主或其他车令牌。`GetCurrentExecution` 只返回已领取且尚未结束的执行，供手动页按秒刷新内存状态。

状态机人工中止分支直接 Abort，无论充磁标志都弃板、清理、报警；取消异常继续传播由Worker识别人工标志并保留循环，普通动作异常同时接受人工中止时清理后直接返回。下一次领取任务创建新令牌。其他车正在执行的流程继续，尚未领取的任务等待恢复线路。人工中止与正常收尾提交互斥：已接受中止不能再提交为 Completed/Waiting，已提交完成的任务不能再被中止。普通故障与宿主停止仍保持原策略。按钮及现场操作见[手动页第 7 节](页面布局/手动操作页面.md#7-中止当前任务)。

### 5.1.1 两层取消判断与重复清理

状态机接收的是本次搬运的linked token，人工中止或宿主停止都能使其IsCancellationRequested=true；这个条件只能说明执行令牌已取消，不能单独判断来自按钮。Worker外层的cancellationToken则是宿主令牌，人工中止不取消它；外层先检查宿主，只有宿主取消才重抛退出，人工分支处理后继续循环。

状态机异常处理中的 `execution.Close()` 在同一锁下关闭新的中止入口，并返回已接受的人工中止标志；不是“暂停工件”或“暂停线路”标志。返回true直接Abort弃板；没有人工请求时按充磁边界HandleFailure。普通Exception分支也检查Close，因为动作失败与按钮取消可能同时发生，此时先得到的异常可能是普通异常而非OperationCanceledException；已接受的弃板意图仍优先。普通异常中的人工分支清理后return，取消异常中的人工分支清理后重抛，均只结束当前任务。

状态机正常异常清理已清CurrentTask；外层FallbackAbort只有还挂着任务才执行。因此通常只产生一条协调器报警，外层ClearRuntime再次置空/Idle属于幂等收尾，不会再清其他工件。若宿主停止与人工中止同时发生，Worker宿主分支优先，消费者按停止要求退出。

### 5.2 CraneTaskChannels

源码：[CraneTaskChannels](../src/AutomatedLine.Application/Runtime/CraneTaskChannels.cs)。每车容量 1，单读者；不是持久队列。配置装载的 Clear 清待领取数据并保留既有通道实例，不重启正在执行的 Worker。

### 5.3 RunFlowAsync

源码：[CraneStateMachine](../src/AutomatedLine.Application/Workers/CraneStateMachine.cs)。初始化和资源获取也在异常捕获范围内。入口先检查已接受的人工中止，再读取共享线路状态；如果此时未运行，关闭本次执行的按钮入口，确认没有人工/宿主取消后走Rollback并返回，不查询设备坐标、不获取资源、不写PLC。

入口回滚将本次工件恢复Waiting，清天车CurrentTask/LockedInterval、置Idle；保留源/目标设备工件引用和信号快照，工件位置、工序及QueueOrder不变。此时尚未交接工件，天车不会获得新的工件引用；不释放其他任务的资源、不升级正常Paused、不新增故障报警或弹窗，statemachine记录回滚原因。恢复线路后可重新生成同一工件候选。

资源争取失败同样走Rollback，等待重新派发；这类资源竞争不触发弃板或故障报警。人工中止已接受时仍优先弃板，宿主取消仍清理后传播，入口未运行不能吞掉它们。

LineControlService的State改由volatile LineState字段发布，写状态仍在原锁内，通知/日志保持原逻辑。入口判断是“是否开始本次搬运”的补充检查，不是全线原子停发：已通过入口的搬运后续正常暂停仍继续，调度已进入的一轮仍可能写通道，尚未领取的任务保留。没有在每个取放步骤检查IsRunning或自动清通道。

### 5.4 TransferContext

源码：[TransferContext](../src/AutomatedLine.Application/Transfer/TransferContext.cs)。每项搬运一个上下文，保存工件、车、程序选项、设备配置缓存和 MagnetCommandStarted，并提供步骤日志方法。

| 原语 | 行为 |
|---|---|
| BaseOfAsync | 设备数据库 XYZ 加车 OffsetXYZ；配置列表在本上下文缓存 |
| MoveAbsoluteAsync / MoveRelativeAsync | 调驱动；结果失败转异常并携带原因 |
| SetCraneSpeedAsync | 下发本车三轴速度/加减速，共九个值 |
| CheckPlateBeforeMagnetAsync | 原位及每次补降后等500ms专用读X11；明确false才按配置仅Z补降，默认最多3次×5mm；耗尽/读失败/运动失败抛异常，仍属充磁前 |
| MagnetOnAsync / MagnetOffAsync | 调充退磁结果接口；成功更新 HasPieceOnCrane，失败抛异常 |
| WaitDeviceAsync | 每 200ms 检查设备缓存点；要求点存在且类型为 bool；握手超时抛异常 |
| WaitCraneAsync | 当前无调用；保留每轮实时读完整天车状态、检查报警与谓词的实现 |
| WriteDeviceAsync | 按逻辑点名调用设备驱动写入，不在此处读取反馈 |

WaitDeviceAsync 没有额外检查快照新鲜度或质量的独立条件。WaitCraneAsync仍保留，但取料X11使用有限补降检查，每个检查点专用读取一次，不走60s有板轮询或后台缓存。

### 5.4.1 取料无板的有限补降与日志

原取料位到位后等500ms读X11。明确0时仅Z调用MoveRelativeAsync(0,0,PickPlateStepMm)，成功后再等500ms重读；任一次1立即返回，随后由Pick设置充磁标志并调用充磁。默认PickPlateRetryCount=3、PickPlateStepMm=5，所以原位加最多3次补降，共最多4次专用读取、15mm累计指令下降。参数位于App.StateMachine，并接入参数页“状态机 → 编辑”。次数0关闭补降，负次数或非正步长在任何检查/补降前抛配置异常。

Z正向是下降，X/Y增量均为0，保留源设备XY和斜床偏移；复用原运动超时、容差和X2下压结果。每步必须返回成功才计入已完成次数；累计距离描述指令量，实际位置由实时读数另列，不能把容差或PressureReached当作刚好下降了5mm。专用X11通信失败、运动失败或取消直接停止，不作为无板重试；过程中尚未开始充磁，普通故障保留工件，人工中止仍按原弃板规则。

IAppLogger的StateMachine类别记录开始配置、每轮等待/检查序号、X11值、已完成补降/上限、单步和累计指令距离、准备下降、运动成功及最终成功/失败/取消。每个X11成功读取的检查点，再经驱动ReadStatusAsync实时读取显示XYZ和编码器XYZ用于诊断，不用共享缓存的HasPlate替换判据；坐标读不到时记“当前位置未知”和Warning，不改变专用X11结果，调用者取消仍传播。失败记录阶段和最后读取位置，说明其不是失败瞬间的新坐标。

日志范例（坐标仅为示例）：

```text
取料：检查第1次，X11=0，已完成补降0/3次，累计指令下降0mm，当前显示坐标X=1000 Y=10 Z=200；编码器X=2000 Y=20 Z=300
取料：X11=0，准备第1/3次补降，仅Z相对下降5mm，计划累计指令下降5mm；下压前当前显示坐标X=1000 Y=10 Z=200；编码器X=2000 Y=20 Z=300
取料有板检查通过：X11=1，已完成补降1/3次，累计指令下降5mm，当前显示坐标X=1000 Y=10 Z=205；编码器X=2000 Y=20 Z=305，下一步才开始充磁
```

每条实际日志由框架附时间，并带天车名和板号/序号；普通补降记Warning、成功/检查记Info、最终失败记Error、取消记Warning。有限次数不是新的总超时，各步运动仍用原期限。五类取料handler共享此方法，放料和手动充磁按钮不执行补降。

### 5.5 六个设备 handler

上料架、双头镗、斜床、研磨机、打号机、下料架分别实现自己的 Pick/Place。只有五种常规来源存在取料充磁步骤；下料架只用于终点放料。

每种 Pick 都在 `await ctx.MagnetOnAsync(...)` 前设置 `ctx.MagnetCommandStarted=true`。标志属于本项取料，不改底层通用充磁方法，不因退磁而清除。

## 6. 状态机公共骨架

1. 核对入口线路状态，未运行且没有已接受取消则回滚本次分配；运行时找工件、源、目标，建立上下文，驱动由流程原语按需取得。
2. TryAcquire 路权；TryReserve 源/目标。后者失败则释放路权并 Rollback。
3. 设置工件/天车 Running；AuditSource 核对内存引用。上料架免审，非上料架的 null 引用允许通过，存在但属于别的工件会失败。
4. 下发本车速度；然后进入 Pick，由 handler 首步等源设备请求。
5. Pick 完整成功：清源引用，车持有工件，位置 OnCrane。
6. Transit 到目标 `(基础X,基础Y,SafeZ)`；保持源预约完成源握手复位；释放源预约、缩路权并同步 Runtime；复位目标握手输出。
7. Place 完整成功：目标持有工件，清车引用，位置 AtDevice，当前工序改目标工序。
8. Finish 回 `(SafeX,目标基础Y,SafeZ)`；释放路权与剩余预约，清车任务/区间、置 Idle；下料为 Completed，否则 Waiting。

源与目标握手复位按点尽力进行，失败点记警告并继续，不保证每个点都写成功；取消异常仍传播。它发生在中转，不是 Abort 内的动作。

实际清理范围是双头镗、斜床、研磨机和打号机；上/下料架为空操作。打号机只清`LoadDone`（0005/PDU4）、`UnloadDone`（0006/PDU5），不清打印内容、内外径和PLC只读输入；源侧完整取料后清、目标侧开始放料前清，沿用同一中转编排和StateMachine日志。

源预约在源握手清理返回后才释放，避免旧任务的清零写入干扰新任务。若清理期间取消，仍沿用状态机的异常分流释放全部资源。

## 7. 五条常用搬运流程逐步说明

核对日期：2026-10-16。以下地址均为程序使用的PDU；斜床#编号是FOCAS宏变量。双头镗带托料架的简化取放交互与三参数Word转换已实施，详见[双头镗地址](设备寄存器地址/双头镗地址.md)。下发工件原始数据不意味着PLC保存原始小数：板长/堵厚Convert.ToInt32，外径先×10再Convert.ToInt32，三项均FC06单Word。

**各搬运共用骨架**：入口线路状态核对 → 路权/源目标预约 → 设速度 → 完整Pick → 工件交给天车 → Transit → 完整Place → 工件交给目标 → Finish。每项等待/运动/写入失败或取消都停止后续步骤，异常按取料充磁边界处理；人工中止始终弃板。

**坐标和天车点位**：基础XYZ为设备配置+本车偏移；`Z取放=基础Z-ZDrop`，SafeZ/SafeX不再加偏移。绝对运动成功后才进行下一动作；触发D4522(X)/D4521(Y)/D4520(Z)沿用底层500ms脉冲和到位轮询。五种Pick均在取料位等500ms专用读X11；明确无板才仅Z追加下降，默认最多3×5mm，各步后再等500ms重读。有板后先设置充磁开始标志，D4510=2→1000ms→0→单读X6=1；Place退磁D4511=2→1000ms→0→单读X7=1。

**各中转共用顺序**：保持SafeZ移到目标基础XY → 持有源预约清源输出 → 清理返回后释放源预约 → 路权缩为目标车体区间，Resize成功才同步Runtime.LockedInterval → 持有目标预约清目标输出。单点清理失败Warning后继续，取消传播。只清下列上位机输出，不清设备反馈或工艺参数：

| 设备 | 中转/手动清理输出（均写0） |
|---|---|
| 双头镗 | DataSentDone 12205、LoadDone 12213、UnloadDone 12221 |
| 斜床 | DataSentDone #1101、CraneLoadInPlace #1102、CraneLoadDone #1103、CraneUnloadInPlace #1104、CraneUnloadDone #1105 |
| 研磨机 | DataTransDone 14623、LoadInPlace 14625、LoadDone 14627、UnloadInPlace 14629、UnloadDone 14631 |
| 打号机 | LoadDone 4（协议0005）、UnloadDone 5（协议0006） |
| 上/下料架 | 无使用中的握手输出，不写PLC |

**各收尾共用顺序**：完整Place成功后先更新目标引用/位置/当前工序；再回`(SafeX,目标基础Y,SafeZ)`，成功后释放路权和剩余预约、清天车任务/区间、Idle。非下料工序工件回Waiting，等待设备加工后下一段搬运；下料工序Completed。异常走原协调器，不自动回安全位或清PLC。

### 7.1 上料架 → 双头镗

**上料架Pick**：

1. 等DI1/10001/PDU0=1（有板允许取料，缓存HasMaterial=true）。
2. 到架基础XY/SafeZ，再下降至Z取放。
3. 执行上述500ms/X11有限补降；耗尽或读取/运动失败尚未开始充磁，保留队列工件。
4. 有板后设置充磁标志，充磁D4510/X6成功，Z回SafeZ；料架不发取料完成PLC位。
5. 完整Pick返回后工件由队列交给天车，位置OnCrane。

**中转**：到双头镗基础XY/SafeZ；上料架无输出需清，释放源预约/缩路权；清双头镗三个输出后开始Place。

**双头镗Place**：

1. 等RequestData 12203=1（设备→上位机）。
2. 顺序FC06写Length 301、Diameter 303、PlugThickness 309；分别按1/10/1倍率Convert.ToInt32后转ushort，例如1200.4→1200、180.6→1806、12.7→13。
3. 三项写成功后DataSentDone 12205=1（上位机→设备）；等RequestLoad 12207=1。
4. Z下降到放料位成功，工件由托料架承托，不发送中间到位信号。
5. 退磁D4511/X7成功，再Z回SafeZ成功，LoadDone 12213=1（图纸称上料到位，要求磁铁上去后再发）。
6. 完整Place返回后交给双头镗，位置AtDevice、工序Boring；收尾成功后Waiting。

### 7.2 双头镗 → 斜床

**双头镗Pick**：

1. 等RequestUnload 12215=1；到源基础XY/SafeZ，再Z下降至取料位。
2. 执行500ms/X11有限补降；有板后标志置true，充磁D4510/X6成功。
3. Z回SafeZ成功，UnloadDone 12221=1；充磁或回升失败不发送下料完成。
4. 完整Pick返回后清双头镗工件引用、交给天车；开始中转。

**中转**：到斜床基础XY/SafeZ；先清双头镗三输出，再释放源预约/缩路权，再清斜床五输出。

**斜床Place**：

1. 等请求数据#1001=1。
2. 顺序写#800工件长度、#801工件直径、#802堵孔70/100、#909斜床工艺1～10；FOCAS按原值double写，不受双头镗Word转换影响。
3. 写数据下发完成#1101=1，等请求上料#1002=1。
4. 在基础XY下降至Z取放；相对Y移动`-YOffset`进入顶尖。
5. 写天车上料到位#1102=1，等尾座夹紧#1003=1。
6. 退磁D4511/X7成功，再绝对回`(基础X,基础Y,SafeZ)`；底层上升顺序先Z后XY，回升后回基础Y。
7. 写天车上料完成#1103=1；完整Place返回后工序Lathing，收尾成功后Waiting。

### 7.3 斜床 → 研磨机

**斜床Pick**：

1. 等请求下料#1004=1。
2. 到`(基础X,基础Y-YOffset,SafeZ)`，保持偏移Y下降至Z取放。
3. 执行500ms/X11有限补降，有板后标志置true，充磁D4510/X6成功。
4. 写天车下料到位#1104=1，等尾座张开#1005=1。
5. 相对Y移动`+YOffset`回中心，再到基础XY/SafeZ。
6. 写天车下料完成#1105=1；完整Pick返回后工件交给天车。

**中转**：到研磨机基础XY/SafeZ；先清斜床五输出，再释放源预约/缩路权，再清研磨机五输出。

**研磨机Place**：

1. 等请求数据RequestData 14603=1。
2. 顺序写RollerDiameter 14633（原直径）、RollerLength 14637（原长度）、MachiningMode 14635（堵孔100→1，70→2）；沿用本机Word/Math.Round转换。
3. 写DataTransDone 14623=1，等请求上料RequestLoad 14605=1。
4. Z下降至Z取放成功，写LoadInPlace 14625=1。
5. 等锁紧完成LoadLockDone 14607=1；退磁D4511/X7成功。
6. Z回SafeZ成功，写LoadDone 14627=1；完整Place返回后工序Grinding，收尾成功后Waiting。

### 7.4 研磨机 → 打号机

**研磨机Pick**：

1. 等请求下料RequestUnload 14609=1；到源基础XY/SafeZ，再Z下降。
2. 执行500ms/X11有限补降，有板后标志置true，充磁D4510/X6成功。
3. 写UnloadInPlace 14629=1，等松开完成UnloadReleaseDone 14611=1。
4. Z回SafeZ成功，写UnloadDone 14631=1；完整Pick返回后工件交给天车。

**中转**：到打号机基础XY/SafeZ；先清研磨机五输出，再释放源预约/缩路权，再清打号机LoadDone/UnloadDone两个输出。

**打号机Place**：

1. 等Busy PDU0（协议0001）=0，设备空闲；此点不是“1空闲”。
2. 顺序写PrintContent起点PDU9（协议000A，UTF-8字节组Word、FC16）、RollerOuterDiameter PDU6（协议0007，原直径）、RollerInnerDiameter PDU7（协议0008，堵孔70/100）；数值沿用本机Word编码。
3. Z下降至Z取放成功，退磁D4511/X7成功，Z回SafeZ。
4. 写LoadDone PDU4（协议0005）=1；无RequestData/RequestLoad/DataSentDone交互，不在Place等待打印加工完成。
5. 完整Place返回后工序Marking，收尾成功后Waiting；下一次Pick才等待加工完成。

### 7.5 打号机 → 下料架

**打号机Pick**：

1. 等ProcessDone PDU2（协议0003）=1，加工/打印完成。
2. 到源基础XY/SafeZ，再Z下降；执行500ms/X11有限补降。
3. 有板后标志置true，充磁D4510/X6成功，Z回SafeZ。
4. 写UnloadDone PDU5（协议0006）=1；完整Pick返回后工件交给天车。

**中转**：到下料架基础XY/SafeZ；保持源预约清打号机两输出，再释放源预约/缩路权。下料架无输出需清。

**下料架Place与收尾**：

1. 等DI3/10003/PDU2原始1（无板允许放板）；驱动反转成HasMaterial=false，必须有实际缓存点，读取失败/缺点不能当空架。
2. 在目标基础XY下降至Z取放，退磁D4511/X7成功，Z回SafeZ；不写FC05放料完成。
3. 完整Place返回后下料架持有工件，位置AtDevice、工序Unloading。
4. 正常回SafeX/SafeZ并释放资源后，工件Completed；本机任务记录仍保留。若收尾失败，仍按充磁后弃板清理该工件引用。

## 8. 坐标与加工参数换算

### 8.1 坐标

基础 XYZ=DeviceConfig.PositionXYZ+Crane.OffsetXYZ。SafeX/SafeZ 是车配置绝对目标，不再叠加偏移。路权使用设备物理 X，不使用加偏移后的目标。

ZDrop按当前`CraneCoordinate.ZDrop`分两类：斜床/研磨为 `Round((直径/2)/0.9537)`；双头镗及其余设备为 `Round((直径/2)/0.9537+(直径/2)/0.866)`。取料、放料使用同类公式，不根据上下料方向切换；双头镗带托料架的交互协议不改变其所属的双系数分支。

| 设备类型 | 取放用途 | ZDrop |
|---|---|---|
| 上料架 | 取料 | `Round((直径/2)/0.9537+(直径/2)/0.866)` |
| 双头镗 | 取料、放料 | `Round((直径/2)/0.9537+(直径/2)/0.866)` |
| 斜床 | 取料、放料 | `Round((直径/2)/0.9537)` |
| 研磨机 | 取料、放料 | `Round((直径/2)/0.9537)` |
| 打号机 | 取料、放料 | `Round((直径/2)/0.9537+(直径/2)/0.866)` |
| 下料架 | 放料 | `Round((直径/2)/0.9537+(直径/2)/0.866)` |

最终编码器绝对目标为`Round(设备PositionZ+本车OffsetZ-ZDrop)`；先对ZDrop取整，再对完整目标取整，均使用`Math.Round`默认的中点取偶数规则。例如直径103.1、设备Z=2000、本车Z偏移=30时：斜床/研磨补偿54，目标Z=1976；双头镗/上下料架/打号机补偿114，目标Z=1916。公式不使用工件长度或堵厚。SafeZ不加偏移，也不减补偿；取料无板时的有限补降在初始取料目标到位后另行追加，仍为仅Z按配置正增量移动，不重新计算直径公式。

斜床 YOffset=`Round((TailstockCenterDistance-工件长度)/2+孔径偏移, AwayFromZero)`。堵孔 100 用 BigHoleOffset，其他用 SmallHoleOffset；按设备 Id 查 App.Transfer.Lathes。配置项不存在返回 0。Big/Small 默认 122/55，顶尖距离默认 0；不能把默认值当现场标定。

### 8.2 参数类型

Modbus 加工参数乘倍率、Math.Round 后转 ushort；没有在驱动里按业务尺寸范围再校验。FOCAS 宏变量通过 double 写入。斜床 #909 取工件 LatheMachiningMode，录入 UI 限定 1～10，宏地址类中的旧“1/2/3”注释不代表当前输入限制。

## 9. 资源与并发

路权锁与设备预约分别有内部锁；工件 Waiting→Assigned 与 Waiting→Paused 竞争同一个 CAS 状态边界；每车 Worker 串行。一次搬运获取路权后再预约设备，失败会释放已获路权并回滚。

多个车并行执行不同搬运。某车故障暂停线路时，其他车已在执行的流程继续；此后不领取新任务。资源释放只针对故障搬运的 TaskId。

### 9.1 UI 弹窗

AlarmManager.Raised 经 App 的Dispatcher.Invoke同步切到 UI 线程，Error/Critical显示系统MessageBox，标题固定“线路异常（已暂停）”，错误图标、确定按钮。正文先放BuildFailure详情，空一行后依次显示来源/资源、系统动作、时间；不单独显示GUID、尺寸、堆栈或次数。弹框关闭不恢复线路、不清 PLC 报警；活动报警可在报警页清空。各异常边界的正文与最新提示原文见[报警处理页面](页面布局/报警处理页面.md#21-异常弹窗固定格式)。

## 11. 日志查找

generation 看源/目标过滤原因，scheduling 看空池、选车、预检查与派发，statemachine 看阶段及逐步执行日志，communication 看实际读写异常，alarm/task 看恢复/弃板，operation 看人工操作。

调度“任务短 ID”使用工件 RuntimeId；路权、预约和状态机部分记录使用 TransportTask.TaskId。应结合板号、序号、车名及源/目标关联，不能认为所有 8 位 ID 必定相同。

## 12. 异常、暂停与重新派发

| 情况 | 工件处理 | 资源/车处理 | 线路 |
|---|---|---|---|
| 入口发现未运行，且无人工/宿主取消 | Waiting，保留设备引用、位置、工序和QueueOrder | 尚未获取资源；清本车任务/区间、Idle，不触碰其他任务锁 | 保持原状态，仅回滚日志、不报警 |
| 获取资源竞争失败 | Waiting，保留位置与引用 | 释放本轮已取得资源，车 Idle | 保持运行 |
| 取料充磁调用前异常 | Waiting，保留源引用、位置、工序和 QueueOrder | 释放路权/预约，清车当前任务/引用/区间，Idle | 故障暂停并报警 |
| 调用取料充磁开始后异常 | Discarded，位置 Discarded，保留列表记录 | 释放资源，清该工件关联源/目标引用及车任务，Idle | 故障暂停并报警 |
| 人工中止所选车当前搬运 | 一律 Discarded，不区分是否充磁 | 直接 Abort，释放本次资源并清运行态；Worker 捕获取消后保留循环 | 立即故障暂停并报警，其他在途车继续 |
| 宿主执行令牌取消 | 按上述取料标志清理 | 清理后重抛，退出车循环 | 宿主停止 |

BuildFailure 记录车名、路线、阶段、异常原因；普通故障附取料充磁边界，人工中止明确附“工件丢弃”，不会误报保留。具体前序动作仍查逐步日志；CraneRuntime.CurrentStep仅保存最近发布的展示步骤，不保存历史，也不作为BuildFailure的额外字段拼接。普通 Exception（包括执行令牌未取消时的内部取消异常）处理后不重抛到 Worker；人工中止与动作异常同时出现时，已接受的人工弃板意图优先。

充磁写入已经开始但通信失败，无法证明实物仍在原设备，按已确认策略弃板；不等 X6 成功才切换异常分类。HasPieceOnCrane 仅反映成功反馈，不能用来代替异常边界。

异常协调器不清 PLC 握手、不移动回安全位。现场处理后重新启动线路，保留的 Waiting 工件按原位置继续生成候选；Discarded 不再生成，但同车可以接受其他 Waiting 工件。人工暂停某 Waiting 工件后再启动，也是保留原设备/工序继续。

## 14. UI 数据与执行数据的区别

主页面“入线顺序”是当前 Queue+Waiting 的连续排位，不是 Runtime.QueueOrder 原始值；派发为 Assigned 时已不计队列排位，尚不能证明物理取料已完成。

大屏设备卡片将内存工件与PLC加工状态分开：工件身份及尺寸来自设备CurrentWorkpiece或上料架队头；研磨机加工状态来自Machining，打号机使用ProcessDone/Busy，双头镗、斜床和料架没有独立加工反馈，不凭内存工件推断加工。关键信号按设备类型筛选，完整缓存点位保留在悬浮详情；断开、质量不良、点位缺失、null或类型不符时显示未知，不作为PLC的0。

设备预约归属从ResourceReservationManager.Snapshot的设备号→TaskId，关联天车当前任务得到名称，仅用于展示。大屏设备仍按ProcessRoute工艺顺序、同类型按Id排列，两行布局不影响调度顺序。

天车任务和路权来自Runtime；任务工件优先按CurrentTask.WorkpieceRuntimeId查询总表，查不到才回退天车持板引用，所以取料前也可以显示任务工件。内存持板与现场X11分别显示，不新增一致性联锁。XYZ使用共享有效快照并压成一行；无有效快照时卡面和悬浮坐标显示“—”。卡面展示有板/充磁/退磁/报警标签，悬浮详情补充全部已采集状态，包括编码器、回原点、具体报警值、下压和接液盘。

### 14.1 只读执行步骤的发布与清理

CraneRuntime.CurrentStep为跨线程可见的展示字符串，不是新增的工艺状态或取消条件。RunFlowAsync登记任务时置为“初始化”；TransferContext.LogStep的两个重载在原有步骤日志时发布说明；CheckPlateBeforeMagnetAsync每轮等待信号稳定前发布第几次检查及补降次数。UI不读取日志文件，也不根据坐标或PLC信号推测动作。

清CurrentTask时同步清CurrentStep，后续LogStep只在仍有当前任务时发布，避免完成/回滚/异常清理后恢复旧步骤。卡片无任务时显示“无任务”，有任务但尚无步骤时显示“已分配，等待执行”。它表示最近发布的步骤，页面1s节拍可能略过短暂的中间动作；动作到位、充退磁反馈和异常处理仍以原业务执行结果为准。

卡片的绑定字段、每种设备关键信号、完整悬浮内容和局部样式见[大屏展示页面](页面布局/大屏展示页面.md)。

## 15. 冷启动核对：提示与等待

[ColdStartChecker](../src/AutomatedLine.Application/Line/ColdStartChecker.cs) 在App打开时及主页面每次启动线路前执行，不限定为内存任务表完全为空。设备使用当前Device.Signals，缺快照则跳过；HasMaterial=true但CurrentWorkpiece为空时记录Warning。启用天车并发等待有效且HasPlate已知的缓存，HasPlate=true但CurrentWorkpiece为空时记录Warning，超时只写system核对未完成日志。

该过程不创建/恢复工件、不写PLC、不释放资源、不设隔离状态，不阻止Start。它会写活动报警及磁盘日志，不只是Console文字；Warning不触发异常错误框。提示“将不参与调度”指残留实物缺内存身份不能生成候选，没有禁用车的代码。缓存不可用时默认最多等待3000ms，各车并发等待，不按数量串行累计；结束后仍按原线路策略启动。
