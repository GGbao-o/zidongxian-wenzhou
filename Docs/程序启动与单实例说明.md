# 程序启动与单实例说明

## 启动顺序

程序启动先创建机器级单实例保护，再显示独立启动窗口。数据库、宿主和冷启动核对仍按原依赖顺序执行：

```text
单实例保护及唤醒监听
→ 显示启动窗口（阶段文字、持续计时）
→ 后台构建配置与依赖容器
→ 异步加载数据库配置、注册设备和天车驱动
→ 后台启动采集、ERP、生成、调度和Worker等宿主服务
→ 保留700ms等待，执行原冷启动核对
→ 在UI线程创建页面ViewModel和主窗口
→ 设置Application.MainWindow，显示主窗口，关闭启动提示
```

线路默认仍为未启动；ERP沿用现有持续监听策略。新增窗口不发运动指令，不跳过冷启动检查，不改工件、调度、PLC握手业务。

## 单实例及重复打开

- 固定内核对象前缀：`Global\AutomatedLine.LineController.v1`，不随EXE目录或版本改变；同一Windows主机不同会话也使用同一保护，不限制其他电脑。
- 命名Mutex以对象存活期判重，不取得线程所有权；不会在异步退出时跨线程释放所有权。
- 第二实例不构建容器、不访问数据库、不启动ERP或采集，使用命名事件请求原实例显示窗口，然后退出。
- 原实例启动中激活启动窗口；启动完成后恢复最小化并请求激活主窗口；退出期间仍拒绝新实例。Windows可能拒绝前台激活，结果记录日志。
- 事件未就绪时最多尝试10次、每次等待50ms；仍失败提示已有实例运行或正在退出，不绕过保护。访问权限不足时提示启动失败并退出，不允许另建一套后台服务。
- 固定标识意味着同一电脑上的两份部署也互斥。若将来同机控制两条独立产线，应先设计产线标识，不能随意换Mutex名称规避保护。
- 跨登录会话的保护不等于可以把其他桌面中的窗口显示到当前桌面。不同账号的事件访问还受Windows对象权限控制，无法通知时仍拒绝第二实例。

## 界面响应和数据库

启动窗口不依赖数据库或业务ViewModel。配置装配和宿主启动在后台执行；查询采用`ToListAsync`并传递取消令牌。同一个DbContext的查询保持串行。

成功的`ServerVersion.AutoDetect`结果按完整连接配置在本进程内复用；连接串改变重新探测，失败不缓存，仍允许恢复后重试。配置CRUD的上下文构造也在后台执行，避免数据库离线时页面构造再次同步联网卡住UI。未新增参数，不修改现有连接串和appsettings.json。

这些改动改善窗口出现与响应，不保证数据库本身连接更快。固定700ms及天车有界等待仍在，实际耗时以启动日志为准。页面构造仍触发原有异步加载，未将全部页面改为懒加载。

## 失败、取消和退出

数据库配置加载失败沿用原策略：记录启动错误和活动报警，再继续打开界面。其他启动失败显示错误提示，并清理已启动服务。

关闭启动窗口会取消初始化并显示退出阶段；同步版本探测无法立刻中断时，等待数据库连接自身期限结束，不能释放正在使用的容器。主窗口原关闭确认保留，取消确认不退出。

确认关闭后先阻止实际关窗，等待初始化结束，再停止宿主并释放容器；宿主停止使用30秒取消期限，异常和超时均记录，随后尽力释放容器。该期限不保证所有第三方同步释放都在30秒内返回。期间继续保留单实例保护，最终在同步OnExit中释放监听及内核对象，避免原async void OnExit尚未清理完进程就结束。

## 日志路径

- 固定启动日志：`EXE目录/Logs/yyyy-MM-dd/startup.txt`。容器建立前也可记录；每行包含PID和累计耗时，阶段完成时另有该阶段耗时。
- 容器日志可用后，同时写入原`system.txt`，位于配置的日志目录日期子目录。默认路径同上；自定义日志根目录不会改变固定启动日志的备用路径。
- 记录首次取得保护、重复启动拦截、原实例唤醒结果、阶段开始/完成/取消/失败、配置降级、核对结果、主窗口显示、退出清理及异常。
- 不主动输出连接串。配置无法解析时优先查看`startup.txt`。

## 验证及现场验收

自动测试覆盖并发申请只成功一个、通知原实例、监听前通知保留、通知端缺失有界失败、释放后重启，以及独立进程被结束后的保护清理。测试使用随机Local名称，不占生产Global标识，不启动宿主、不连接数据库或PLC。

现场部署后还需验收：

1. 启动阶段连续双击多次，只保留一个控制进程；启动窗口文字和计时持续刷新。
2. 主窗口最小化后再次双击，原窗口恢复，不新增后台采集或ERP实例。
3. 数据库离线时提示保持响应，连接失败后按原策略进入主界面，可在日志定位耗时。
4. 启动中关闭、配置错误、主窗口确认关闭均能退出；取消关闭确认则继续运行。
5. 退出中再次双击不建立第二套服务；退出后可重新打开。
6. 核对原冷启动报警、ERP监听及人工启动线路行为保持一致。
