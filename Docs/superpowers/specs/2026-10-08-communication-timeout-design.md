# 通信超时与执行器取消处理

## 已确认的业务目标

通信失败允许丢弃当前板并进入故障暂停。人工处理现场并恢复线路后，同一天车应继续消费新任务；只有宿主关闭或执行器令牌真正取消时才退出执行循环。

## 方案与边界

只删除 Worker 中的 throw 可以保住循环，但无法纠正超时分类。采用已在会话中确认的方案：Modbus 内部超时转 TimeoutException；状态机与 Worker 的取消分支均检查传入令牌是否真的取消。

- ModbusTcpClient.ExchangeAsync 的异常处理覆盖自动连接、发送及响应读取；失败断开，下一次请求重新连接。超时保留原取消异常作为 InnerException。
- CraneStateMachine 与 CraneWorker 使用取消过滤器；非调用者取消进入普通故障处理，保持弃板、释放资源和故障暂停。
- 真正宿主取消仍沿原退出路径处理，不添加自动恢复线路、重试当前板或重建循环的机制。
- 不处理分析报告中的其他问题，不连接现场设备、数据库或原生 FOCAS。

## 验证

本机回环 TCP 服务不回复时，真实客户端必须抛 TimeoutException；调用者主动取消时仍抛 OperationCanceledException。超时后下一请求能重连成功。

Worker 回归使用真实状态机、注册表、预约和路权管理器，注入流程内及流程入口的非调用者取消异常：首单丢弃、资源释放、故障暂停，人工恢复后第二单完成。另验证真实取消继续传播及停止执行器能清理在途任务。
