# 异常握手清理与手动模式

更新日期：2026-10-21。源码：[CraneStateMachine](../src/AutomatedLine.Application/Workers/CraneStateMachine.cs)、[TransferContext](../src/AutomatedLine.Application/Transfer/TransferContext.cs)、[CraneService](../src/AutomatedLine.Infrastructure/Communication/CraneService.cs)、[手动服务](../src/AutomatedLine.Infrastructure/Manual/ManualOperationService.cs)。

## 1. 异常后的设备握手复位

普通故障尚未开始取料充磁时，保持现有保板策略，不新增PLC复位。充磁开始后的故障、进入弃板路径的人工中止和宿主取消，在原内存清理及资源释放前，先故障暂停并尽力复位设备握手。未运行入口或资源竞争回滚不写PLC。

TransferContext分别记录是否已进入源Pick、目标Place；清理按下列条件筛选，不能只遍历源/目标，也不能只依赖当前工件引用：

| 条件 | 处理 |
|---|---|
| 本任务未进入该侧交互 | 跳过 |
| 设备预约已释放、没有预约或属于其他任务 | 跳过 |
| 设备当前引用其他RuntimeId工件 | 跳过 |
| 已交互、仍持有本任务预约、当前引用为空或为本工件 | 调用该类型ClearHandshakeAsync |
| 未装载设备/驱动、无执行上下文 | 留日志并跳过，不猜测归属 |

取料成功后源引用已经清空，中转失败但源预约尚未释放时仍需要复位源握手。源预约释放后即使后来挂上其他工件，也不会被旧任务写0。目标Place执行参数或握手写入失败时，目标可能尚未建立工件引用，仍能按本任务预约和交互标志清理。

顺序为：暂停线路→逐设备筛选→保持预约/路权等待复位结束→原TaskAbortCoordinator释放资源、按RuntimeId清引用并弃板/报警。内存处置本身仍沿用协调器原有实现；没有执行上下文的Worker兜底只执行原内存清理，不猜测PLC清理对象。

复用各Handler的ClearHandshakeAsync，只写输出握手0，不清工艺参数、设备输入，不发天车运动或急停。单点写失败只记Warning并继续；每台设备使用独立的清理取消期限，复用Collection.CommunicationTimeoutMs（默认3000ms），不复用可能已取消的任务令牌。整台超时或异常也只留Warning并继续其他设备/原异常处置，不能用清理异常覆盖原故障。有限期限取消后等待原调用结束，不将仍可能写PLC的调用丢到后台再释放预约。

statemachine.txt记录清理开始、设备/侧别、搬运ID、跳过原因、逐点写入、成功数量及超时/失败原因。清理成功数量不代表所有点均已清，PLC应答也不等于读回确认；communication.txt沿用底层报文日志。

## 2. 手动页设置模式

动作卡新增“设置手动模式”，通过IManualOperationService和ICraneDriver的新SetManualModeAsync调用独立实现：FC06写D4001=2并等待应答，再写D4500=2并等待应答。首次写失败不发第二次；任一失败只显示失败结果。每次点击都实际写两个地址，不使用或修改EnterManualAsync的_manualModeSet缓存，不改变现有运动方法。重复点击的执行互斥沿用异步命令默认行为。

operation.txt记录两个地址各自的下发和应答。按钮成功只表示两个写入已应答，Message明确提示状态等待后台读回；不直接把左侧显示值改成2。

## 3. 模式状态采集与显示

CraneStatusDto新增可空整数ModeCommand、ManualEnable。完整ReadStatusAsync在原14次请求后增加FC03单Word读D4001、D4500，正常一轮共16次；不扩大连续读取范围，不添加采集服务、连接或缓存。ReadRawStatusAsync、运动到位PollAxesAsync仍沿用原读取范围。

模式单点读取失败时该项为null，记录地址和失败原因；其他已读坐标/状态仍可发布。下一点通过原客户端按需重连。字段保留原始无符号Word数值，不把非0转换成“手动”，也不用上次成功值或0替代失败。

左侧模式区显示“模式指令D4001”“手动使能D4500”，2为对应手动/使能指令值，不把命令寄存器冒充额外的PLC模式确认输入。页面从同一ICraneStateProvider共享快照刷新；未选车、切车无快照、单点失败或快照过期均显示“未知”，页面刷新不新增PLC请求。按钮写入成功后等待实际后台读取更新。

## 4. 验证范围

本机TCP桩核对按钮连续两次均写4001/4500、原缓存真假均保持不变、部分写失败不能报成功；核对模式FC03读取和单点未知、原有坐标符号解析。真实状态机搭配桩驱动验证源空引用中转失败、目标空引用参数失败、其他工件和他人预约保护、持有资源等待清理、清理失败/超时继续原弃板、充磁前不清及人工中止/宿主取消。测试不连接现场PLC。
