# 上料架与下料架点位

核对日期：2026-10-08。源码：[RackAddress](../../src/AutomatedLine.Infrastructure/Communication/RackAddress.cs)、[DeviceModbusMaps.Rack](../../src/AutomatedLine.Infrastructure/Drivers/DeviceModbusMaps.cs)、[LoadRackHandler](../../src/AutomatedLine.Application/Transfer/Handlers/LoadRackHandler.cs)、[UnloadRackHandler](../../src/AutomatedLine.Application/Transfer/Handlers/UnloadRackHandler.cs)。

## 1. 当前通信映射

Modbus TCP，IP来自设备配置，固定端口10000、站号254。上下料架即使IP相同，也按各自设备Id创建独立驱动/连接；没有按IP统一批量采集。

| 类型 | 唯一点名 | 区域/功能码 | 0基PDU地址 | 值 |
|---|---|---|---:|---|
| LoadRack | HasMaterial | DiscreteInput，FC02 | 0 | 1有板，0无板 |
| UnloadRack | HasMaterial | DiscreteInput，FC02 | 1 | 1有板，0无板 |

每个驱动ReadAllSignalsAsync只读自身这个输入。旧文档中的连续读0～2、线圈读0～3、FC05上料/下料完成均不是当前料架映射，已移除。

## 2. 上料架工件来源与取料

工件来自RuntimeTaskManager队列，而不是由有板信号自动生成。只有Location=Queue、TaskState=Waiting的最小QueueOrder队头可生成候选，使用第一个启用上料架；HasMaterial=true、已连接、未预约等条件通过才派发。

Pick实际顺序：等架HasMaterial=true → 基础XY/SafeZ → Z下降 → 等500ms、单次读天车X11 → 设置取料充磁标志 → 充磁 → Z回SafeZ。没有料架完成位写入。Pick返回后工件位置改OnCrane。

有板但没有队头不会自动新增板号/工件；冷启动核对只报警，不凭这个位恢复工件身份。

## 3. 下料架放料

候选要求空架HasMaterial=false等目标条件；Place再次WaitDeviceAsync等待真实缓存点存在且为false，不能把“没采到点”直接算空架。

然后在目标XY下降 → 退磁 → Z回SafeZ，无FC05写入。Place完整完成后建立下料架内存工件引用/Unloading工序，正常回安全位才Completed。

架上Completed工件记录仍在列表，删除仅清内存引用和记录，不移走实物；物理有板仍由下一轮PLC输入显示。

## 4. 大屏的两类数据

卡片“空闲/加工中”按架CurrentWorkpiece，不按HasMaterial。上料架悬浮工件资料使用外部传入的队头，已同步修复；有队头本身不会变“加工中”。下料架悬浮工件用自身引用。

点位区域只显示“有料=1/0”，来源后台缓存；连接失败显示无数据、红框。启用多台上料架时，每张卡都可展示同一个全局队头，并不表示当前生成器会并行从多架取料。
