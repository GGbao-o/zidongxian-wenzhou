## 1. 当前通信映射

Modbus TCP，IP来自设备配置，固定端口10000、站号254。上下料架即使IP相同，也按各自设备Id创建独立驱动/连接；没有按IP统一批量采集。

| 类型 | 现场输入 | 文档地址 | 0基PDU地址 | 原始信号含义 | 业务点HasMaterial |
|---|---|---|---:|---|---|
| LoadRack | DI1，FC02 | 10001 | 0 | 1允许取料（有板），0不允许取料（无板） | 同向：原始1→true，原始0→false |
| UnloadRack | DI3，FC02 | 10003 | 2 | 1允许放板（无板），0不允许放板（有板） | 反转：原始1→false，原始0→true |

每个驱动ReadAllSignalsAsync只读自身一个FC02输入。DI2/10002/PDU1和DI4当前不用于取放判断；地址类备用InputStart=0、InputCount=3覆盖DI1到DI3，但当前不合并连续采集。

仅下料架增加可写线圈PlaceDone：DO2/00002，对应0基PDU地址1，使用FC05单线圈写入。业务写1在线路上编码为0xFF00，写0编码为0x0000；不使用FC06寄存器写入，不增加FC01读回。此输出线圈PDU1与未使用的DI2输入PDU1属于不同区域，不混用。上料架不增加完成输出。

下料架在DeviceModbusMaps中对HasMaterial启用InvertDiscreteInput，ModbusDeviceDriver读取DI3成功后取反，后台缓存保存归一化后的有料状态。取反只用于该下料架离散输入，其他点位默认不反转；通信失败继续抛异常，由采集器发布失败/空快照，不伪造允许放板。

## 2. 上料架工件来源与取料

工件来自RuntimeTaskManager队列，而不是由有板信号自动生成。只有Location=Queue、TaskState=Waiting的最小QueueOrder队头可生成候选，使用第一个启用上料架；HasMaterial=true、已连接、未预约等条件通过才派发。

Pick实际顺序：等架HasMaterial=true → 基础XY/SafeZ → Z下降 → 等500ms专用读天车X11，无板按配置仅Z有限补降 → 有板后设置取料充磁标志 → 充磁 → Z回SafeZ。没有料架完成位写入。Pick返回后工件位置改OnCrane。

默认追加3次×5mm，每次成功后再等500ms重查，共最多4次专用读取、15mm累计指令下降；仍无板或读/运动失败按充磁前保留队列工件，不能将通信失败当无板继续下降。配置与实际位置日志见[应用层说明](../应用层设计.md#541-取料无板的有限补降与日志)。下料架Place不执行这段补降。

有板但没有队头不会自动新增板号/工件；冷启动核对只报警，不凭这个位恢复工件身份。

## 3. 下料架放料

候选要求空架HasMaterial=false等目标条件，对应现场DI3/10003原始值1（允许放板）；原始0转换为HasMaterial=true，候选不允许放料。Place再次WaitDeviceAsync等待真实缓存点存在且为false，不能把“没采到点”直接算空架。候选与Handler继续使用原有HasMaterial判断，不直接读取或比较原始DI3。

完整顺序：等待HasMaterial=false → 在目标XY下降 → 退磁 → Z回SafeZ成功 → FC05/PDU1的PlaceDone写1并等待应答 → 保持1000ms → PlaceDone写0并等待应答 → Place完成，再进入原Finish。触发时XY仍在下料架上方，不等待整车回SafeX；保持时间从写1返回后开始计算，期间继续持有原目标预约和路权。Place完整完成后才建立下料架内存工件引用/Unloading工序，正常回SafeX并释放资源才Completed。

下降、退磁或回升失败不发送脉冲。开始尝试写1后，无论写1应答失败、保持期间取消或正常结束，都在finally单次尝试写0；复位使用独立取消源，期限复用本搬运的Collection.CommunicationTimeoutMs，非正值兜底3000ms，不受已取消的搬运令牌影响。写0失败记录警告；已有写1/保持异常时保留原异常，否则传播复位异常，不得记录Place完成。写1不自动重试，不补发完整脉冲；通用ClearHandshakeAsync仍为空操作，避免中转/Finish重复写入。

statemachine日志记录回升、PDU1写1开始/应答、保持1000ms、写0开始/应答或复位失败；communication记录FC05点名和PDU地址。此功能不新增JSON参数，原取放判断与采集点不变。

架上Completed工件记录仍在列表，删除仅清内存引用和记录，不移走实物；物理有板仍由下一轮PLC输入显示。

## 4. 大屏的两类数据

卡片“空闲/加工中”按架CurrentWorkpiece，不按HasMaterial。上料架悬浮工件资料使用外部传入的队头，已同步修复；有队头本身不会变“加工中”。下料架悬浮工件用自身引用。

点位区域只显示“有料=1/0”，来源归一化后的后台缓存；下料架显示有料0对应原始DI3=1（无板可放），显示有料1对应原始DI3=0（有板不可放），并非原始输入值。连接失败显示无数据、红框。启用多台上料架时，每张卡都可展示同一个全局队头，并不表示当前生成器会并行从多架取料。冷启动HasMaterial=true的提示也使用同一归一化语义。
