# 天车寄存器地址与操作说明

数据库坐标+天车偏移量=实际位置

实际位置-数据库坐标=天车偏移量

目标-当前+显示值=-9999



核对日期：2026-10-14。本文根据当前工作区的 `CraneAddress`、`CraneService`、`ManualOperationService` 和手动页 XAML/ViewModel 编写，记录上位机实际使用的地址、读写方法和按钮行为。

## 1. 通信与地址规则

| 项目 | 当前实现 |
|---|---|
| 协议 | Modbus TCP |
| PLC IP | 对应天车的数据库配置 |
| TCP 端口 | 固定 502 |
| UnitId | 固定 1 |
| 单次通信请求期限 | 客户端默认 3000ms；天车驱动创建客户端时没有另传期限 |
| 连接 | 请求时发现未连接就自动连接；通信异常后断开，后续请求可重新连接 |
| 请求串行化 | 同一天车连接由 `SemaphoreSlim` 串行收发；一次完整动作仍包含多个独立请求 |
| D 地址 | 线上 PDU 地址直接使用 D 编号，例如 D4510 → 4510，不再减 1 |
| X 地址 | X 编号按八进制解释，线圈地址 = 63488 + 物理序号；X11 是第 9 号 → 63497 |

功能码：

| 功能码 | 使用场景 |
|---|---|
| FC01（0x01） | 读 X 区线圈，每次读一个点 |
| FC03（0x03） | 批量读状态寄存器与速度寄存器 |
| FC06（0x06） | 写一个 16 位 Word：速度、模式、命令触发/复位 |
| FC16（0x10） | 写一个轴的 32 位 DINT 目标，占连续两个寄存器 |

32 位坐标按**低字在前、高字在后**排列。例如目标 100000：低字 34464、高字 1；写 X 目标时分别放 D3102、D3103。每个 Word 在 Modbus 报文内部仍按高字节在前发送。

本文没有把批量读取区中未解析的地址认定为有效业务点位。D4509、D4519 等未在当前驱动定义和使用的地址也不推断用途。

## 2. 只读状态寄存器

驱动先用 FC03 从 **5000 连续读 30 个 Word（D5000～D5029）**，实际解析以下字段。

| PLC 地址 | PDU 地址 | 类型/读取方式 | 用途及判断 |
|---|---|---|---|
| D5006 | 5006 | 单 Word | X 已回原点；非 0 为完成 |
| D5007 | 5007 | 单 Word | Y 已回原点；非 0 为完成 |
| D5008 | 5008 | 单 Word | Z 已回原点；非 0 为完成 |
| D5011 | 5011 | 单 Word，保留原值 | 伺服报警；非 0 表示有报警 |
| D5012 | 5012 | 单 Word，保留原值 | PLC 伺服指令报警；非 0 表示有报警 |
| D5013 | 5013 | 单 Word，保留原值 | PLC 报警；非 0 表示有报警 |
| D5014～D5015 | 5014～5015 | 有符号 32 位 DINT，低字在前 | X 绝对编码器坐标 |
| D5018～D5019 | 5018～5019 | 有符号 32 位 DINT，低字在前 | X 显示值坐标 |
| D5020 | 5020 | 单 Word，有符号 16 位 INT，符号扩展为 int | Y 绝对编码器坐标 |
| D5022 | 5022 | 单 Word，有符号 16 位 INT，符号扩展为 int | Y 显示值坐标 |
| D5023 | 5023 | 单 Word，有符号 16 位 INT，符号扩展为 int | Z 绝对编码器坐标 |
| D5025 | 5025 | 单 Word，有符号 16 位 INT，符号扩展为 int | Z 显示值坐标 |

`HasAlarm` 是三个报警原值中任意一个非 0。页面显示具体数值；这里没有报警编号释义表。

**D5029 不是有板信号。当前有板判断使用 X11。** Y/Z 四项坐标反馈均为单 Word 有符号 INT，范围 -32768～32767，例如 0xFFFF 解码为 -1、0x8000 解码为 -32768；不组合相邻 Word，不缩放。解析结果统一供后台缓存、页面显示、运动坐标换算及到位轮询使用。X 反馈仍为有符号 32 位 DINT；速度和报警 Word 不做此有符号转换。

## 3. X 区只读信号

以下全部通过 **FC01** 读取，读到 1 → `true`，0 → `false`。

| PLC 信号 | 线圈 PDU 地址 | 含义 | 当前主要用途 |
|---|---|---|---|
| X0 | 63488 | 接液盘门开到位 | 状态展示；开盘按钮自身不等待该反馈 |
| X1 | 63489 | 接液盘门关到位 | 状态展示；关盘按钮自身不等待该反馈 |
| X2 | 63490 | 磁铁下压限位 | Z 下降的运动轮询中读取，触发下压收尾 |
| X3 | 63491 | X 物理原点 | 状态展示，与 D5006 回原点完成是不同字段 |
| X4 | 63492 | Y 物理原点 | 状态展示，与 D5007 回原点完成是不同字段 |
| X5 | 63493 | Z 物理原点 | 状态展示，与 D5008 回原点完成是不同字段 |
| X6 | 63494 | 充磁反馈 | 充磁脉冲结束后单次确认 |
| X7 | 63495 | 退磁反馈 | 放磁/退磁脉冲结束后单次确认 |
| X11 | 63497 | 检测有板 | 自动取料的充磁前检查、冷启动核对、状态展示 |

### 3.1 完整状态读取与页面刷新

一次正常 `ReadStatusAsync()` 顺序为：

1. FC03：D5000 起读 30 个 Word。
2. FC03：D2501 起读 21 个 Word。
3. FC01：依次读X11、X6、X7、X2、X0、X1、X3、X4、X5，再读X/Y/Z Busy（B531/12819、B536/12824、B541/12829）。
4. FC03：分别单Word读D4001模式指令、D4500手动使能，供手动页显示原值；2为对应手动/使能指令，单点读取失败为未知。

正常完成时共 **16 次通信请求**，各点是在各自读取时取得，整份 DTO 不是 PLC 原子快照。新增模式读取仅在完整展示快照中，运动使用的ReadRawStatusAsync和PollAxesAsync不增加请求。

大屏卡面直接展示共享缓存中的有板/充磁/退磁/报警标签，悬浮详情显示全部已解析状态；这不增加本节读取次数。无有效状态时信号标签显示未知、XYZ显示“—”；单点失败仍保留其他点的有效值。任务工件、内存持板、路权和最近执行步骤来自Application内存，不是新增的天车PLC寄存器，显示规则见[大屏文档](../页面布局/大屏展示页面.md)。

状态/速度批量读取失败，完整状态返回null；X区或Busy某点读取失败，仅该点为null并记录点名及地址警告。手动页左侧Busy显示1（运动中）、0（停止）、未知“—”；只使用后台缓存，运动判定仍实时读Busy。手动页未知值显示“—”，不把未知显示成“否”。

Application 的 `CraneStateCollector` 为每台启用天车独立采集；同一台车一轮读完才等待下一轮，默认轮间等待 500ms。结果按 CraneId 存入 `CraneStateStore`，不写入设备的 `Device.Signals`。

手动页与大屏默认每 1s 从共享缓存更新各自 ViewModel，再由 `PropertyChanged` 更新画面。手动页选车、点击“刷新”也会立即读取缓存；**“刷新”不额外发起 PLC 状态读取**。默认有效快照最大年龄为 2000ms，按读取开始时刻计算；失效快照不继续作为有效状态使用。

运动到位、X2 下压、充退磁反馈和自动取料 X11 检查仍然现场读取，不使用这个展示缓存。详见[天车状态采集设计](../天车状态采集设计.md)。

## 4. 速度、模式与运动目标地址

### 4.1 三轴速度/加减速

设置速度按表中顺序逐项 **FC06 写单 Word**，输入 int 转为 ushort；读取时 FC03 从 2501 连续读 21 个 Word，取其中九项。

| 顺序 | PLC/PDU 地址 | 参数 |
|---|---|---|
| 1 | D2501 / 2501 | X 速度 |
| 2 | D2502 / 2502 | X 加速度 |
| 3 | D2503 / 2503 | X 减速度 |
| 4 | D2510 / 2510 | Y 速度 |
| 5 | D2511 / 2511 | Y 加速度 |
| 6 | D2512 / 2512 | Y 减速度 |
| 7 | D2519 / 2519 | Z 速度 |
| 8 | D2520 / 2520 | Z 加速度 |
| 9 | D2521 / 2521 | Z 减速度 |

这些数值按 PLC Word 原值下发，没有在该方法中作倍率换算或范围校验。具体速度/加减速物理单位按 PLC 定义。九次写入全部结束才返回 `Completed`，中间失败会停止后续写入，不回滚已经写入的值。此操作不调用手动模式前置。

手动页“设置速度”使用页面九个输入，不修改数据库；自动搬运开始时仍按对应天车的数据库速度配置下发。

### 4.2 模式前置

| PLC/PDU 地址 | 写入值 | 用途 |
|---|---|---|
| D4001 / 4001 | 2 | 请求手动模式 |
| D4500 / 4500 | 2 | 手动操作使能 |

`EnterManualAsync()` 顺序写 D4001=2、D4500=2，两个写入成功后缓存 `_manualModeSet=true`。后续需要该前置的命令跳过重复模式写入；不再回读模式进行确认，也不将这两个值按脉冲复位为 0。

显式连接/断开和下压收尾会使这个缓存失效；底层请求自动重连本身没有同步清除此缓存。当前没有独立的“切自动模式”按钮或模式值 1 的写入流程。

手动页新增独立SetManualModeAsync入口，每次点击依次FC06写D4001=2、D4500=2，等待各次应答，不使用也不修改EnterManualAsync的缓存。首项失败不继续第二项；两次写入成功只表示已应答，左侧反馈由后台FC03读回更新，模式单点失败显示未知。operation.txt记录各地址下发及应答，现有运动方法及前置逻辑不变。详见[异常握手清理与手动模式](../异常握手清理与手动模式.md)。

自动搬运也调用同一个驱动和上述运动/磁铁方法；程序线路运行状态与 PLC 的这两个模式寄存器分别管理。

### 4.3 目标与触发

| 轴 | 目标寄存器 | 目标写入方式 | 触发寄存器 | 触发方式 |
|---|---|---|---|---|
| X | D3102～D3103 / 3102～3103 | FC16，两 Word，有符号 32 位 DINT | D4522 / 4522 | FC06：2 → 500ms → 0 |
| Y | D3104～D3105 / 3104～3105 | FC16，两 Word，有符号 32 位 DINT | D4521 / 4521 | FC06：2 → 500ms → 0 |
| Z | D3106～D3107 / 3106～3107 | FC16，两 Word，有符号 32 位 DINT | D4520 / 4520 | FC06：2 → 500ms → 0 |

当前“绝对移动”和“相对移动”都走这一组地址。每个轴的目标单独发送一次 FC16，没有一次性合写三个轴。

## 5. 绝对移动按钮

入口：手动页 `AbsX/AbsY/AbsZ` → `ManualOperationService.MoveAbsoluteAsync()` → `CraneService.MoveAbsoluteAsync()`。

### 5.1 坐标换算

输入是**期望的绝对编码器坐标**。驱动先即时读原始状态（状态区和速度区），然后逐轴计算：

```text
写入目标 = 输入的绝对目标 - 当前绝对编码器坐标 + 当前显示值坐标
```

例如 X：当前编码器 10000、显示值 2000、输入目标 12000，则 D3102/3103 写 4000；到位判断仍比较 X 编码器与 12000，而不是比较编码器与 4000。

绝对移动入口不会把输入0当作跳过轴：0是目标坐标。底层MoveAsync统一使用`CraneService.SkipAxis = -9999`作为不参与轴的标记，该常量在int范围内；-1恢复为普通有效负坐标，仍写DINT目标、触发运动、读取Busy并检查到位。-9999保留作内部标记：写入值为该标记时跳过写入/触发/复位，到位目标为该标记时跳过比较/Busy读取；不要将其当作实际目标。分阶段等待、相对零增量轴和日志统一使用同一常量。

### 5.2 写入与执行

1. 即时读状态，计算三个写入值；用目标 Z 与当前 Z 编码器比较，确定升降方向。
2. `MoveAsync` 确保模式前置，再按 X、Y、Z 顺序写入参加运动的目标。
3. 根据 Z 方向下发触发脉冲，顺序见第 7 节。
4. 即时轮询编码器坐标，直到普通到位、下压返回、轮询超时、通信失败或取消。
5. `finally` 对参加写入的轴再尝试将 D4522/D4521/D4520 写 0，使用不可取消令牌；复位失败记警告，不覆盖原结果。

这里不会修改自动搬运工件的位置、工序或设备预约，也不会更新自动任务归属。

## 6. 相对移动按钮

入口：手动页`RelativeStep`统一步长输入 + `X+/X-/Y+/Y-/Z+/Z-`六个按钮 → ViewModel将所选轴映射为正/负步长、其他轴传0 → `ManualOperationService.MoveRelativeAsync()` → `CraneService.MoveRelativeAsync()`。步长要求为大于0的整数mm；每次点击只执行一次移动，六个按钮共用同一个异步命令。

1. 增量全为 0，直接返回 `Rejected`，提示“相对值不能全为 0”。
2. 即时读取当前显示值坐标和速度区。
3. 非零轴计算`目标显示值 = 当前显示值 + 输入增量`，即使结果为-1也正常执行；零增量轴内部填`CraneService.SkipAxis`（-9999），表示不参加。
4. 模式前置后把这些目标写入 D3102～D3107，用 D4522/D4521/D4520 触发。
5. 轮询**显示值坐标**，与计算出的显示目标比较。
6. 按同样的运动 `finally` 逻辑尝试复位触发寄存器。

例如当前显示值`(2000, 300, 100)`，页面输入步长50点击X+，传入`(50, 0, 0)`，X目标2050，Y/Z不参加；步长5点击Z+，传入`(0, 0, 5)`，Z目标105，X/Y不参加。当前约定Z正增量为下降、负增量为上升。

相对移动最终调用绝对目标寄存器。`JogAsync` 的 D4501～D4505 是另一条点动接口，当前页面相对移动按钮没有调用它，详见第 11 节。

## 7. 运动触发顺序、到位与下压

### 7.1 Z 方向控制顺序

当前代码约定 **Z 增大为下降，Z 减小为上升**：绝对移动比较目标与当前编码器；相对移动比较增量与 0。

| Z 方向 | 触发/等待顺序 |
|---|---|
| 下降（内部方向 1） | X/Y 触发脉冲 → 轮询 X/Y 到位 → Z 触发脉冲 → 轮询全部参加轴，并检查 X2 |
| 上升（内部方向 2） | Z 触发脉冲 → 轮询 Z 到位 → X/Y 触发脉冲 → 轮询全部参加轴 |
| 不变（内部方向 0） | 全部参加轴同阶段触发 → 轮询全部参加轴 |

同阶段触发实际是：顺序写各参加轴的触发值 2 → 统一等 500ms → 顺序写各轴为 0。它不是一条报文同时写入所有触发位，也不是保持 2 等运动到位才写 0。

### 7.2 普通到位

每次 `PollAxesAsync` 建立一个独立期限，然后循环：

```text
检查取消 → 等 200ms → 即时读状态区与速度区
→ 选择编码器/显示值坐标 → 必要时读 X2
→ 即时FC01读取本阶段参加轴Busy（X=12819、Y=12824、Z=12829）
→ 全部参加轴误差≤配置容差且Busy=0，才算普通到位
```

| 配置 | 默认值 | 用途 |
|---|---|---|
| `App:Crane:MoveTimeoutMs` | 60000ms | 每次运动轮询的期限 |
| `App:Crane:PositionToleranceMm` | 30mm | 普通到位：每个参加轴绝对误差≤容差，并且该轴Busy=0 |
| `App:Crane:PressureToleranceMm` | 15mm | X2 下压触发时的 Z 误差判据 |

普通到位返回成功码`InPosition`，±30mm边界包含在内。坐标已在容差内但Busy=1时继续等；Busy=0但误差超限同样继续等。未参与轴（目标为SkipAxis/-9999）不读取Busy；真实目标-1仍必须同时满足位置容差及Busy=0，不要求见到过Busy=1或Done=1。只用即时反馈，不取后台缓存。位置、速度区或参与轴Busy遇到连接关闭/重置、Socket异常或请求超时时，本轮反馈作废，下一轮等待200ms后重新读取位置及全部参与轴Busy，底层自动重连；不能混用上轮位置、旧Busy或将未知当0。重读不重发目标及运动触发，不提前释放预约、路权或丢弃工件。

每次PollAxes使用一个固定运动期限，采用单调计时；等待、读取、连接锁排队、重连和失败均计入，重试不续期，单次读取也受剩余期限取消。到期限仍未确认到位返回`Timeout`，日志/结果附最后完整反馈、累计/连续读取失败次数及最后原因。调用者取消立即传播；非法地址等Modbus异常响应、功能码/长度错误等协议故障不重试。协议错误用IOException子类型ModbusProtocolException区分，仍按原规则断开并记录报文。首次失败及持续每2秒记录业务告警，完整读取恢复时记录恢复，底层每次通信失败诊断保留。

X2读取失败仍返回false并记录警告；下压分支仍先于普通判据，沿用急停/清报警及原15mm下压容差。PressureStopAsync中的写入不在读取重试范围，失败直接传播。200ms为循环等待，实际采样间隔还包含通信和连接锁排队。默认60s限定一次轮询，不是整次按钮的耗时上限：分阶段轮询分别计时，目标写入、触发、下压收尾及finally尽力复位仍使用原规则。

当前运动轮询虽然会读到 D5011/12/13，但没有把它们纳入 `PollAxesAsync` 的成功/失败判定。调度器的报警筛选属于调度阶段，不能据此把运动到位方法描述为持续报警监控。

### 7.3 X2 下压收尾

只在 Z 下降后的最终轮询阶段启用 X2 监视。X2=1 时，先执行：

```text
D4518=2 → 200ms → D4518=0
→ 手动模式缓存失效
→ D4001=2 → D4500=2
→ D4514=2 → 200ms → D4514=0
```

这段收尾使用 `CancellationToken.None`。下压使用的急停地址实际是 **D4518**；D4523 虽有常量定义，当前流程没有使用它。

随后用本轮读取的 Z 与目标 Z 比较：

- 误差 ≤ 下压容差：返回 `PressureReached`，为成功。
- 误差 > 下压容差：返回 `PressureOutOfRange`，为失败。

X2 分支先于普通 XYZ 到位分支，并且只用 Z 误差决定下压结果。若 X2 读取失败，当前方法记录警告并按未触发继续；如果急停/清报警收尾本身抛异常，则进入运动通信失败处理。

运动超时或取消后的触发复位只是写触发寄存器 0，不会因此自动发送急停。

## 8. 手动操作页全部按钮

## 9. 充磁与放磁的完整处理

### 9.1 充磁

```text
确保 D4001=2、D4500=2（已缓存则跳过）
→ FC06 写 D4510=2
→ 等固定500ms
→ FC06 写 D4510=0
→ 按App.Crane.MagnetFeedbackDelayMs等待（默认1000ms）
→ FC01 单次读 X6（63494）
```

- X6=1：返回 `Completed`、成功。
- X6=0：返回 `Rejected`、失败，提示“充磁失败：X6=0，反馈未确认”。
- 通信异常：返回 `Communication` 或 `NotConnected`，按捕获异常时的连接状态区分。
- 取消异常：向上抛出 `OperationCanceledException`。

### 9.2 放磁/退磁

```text
确保 D4001=2、D4500=2（已缓存则跳过）
→ FC06 写 D4511=2
→ 等固定500ms
→ FC06 写 D4511=0
→ 按App.Crane.MagnetFeedbackDelayMs等待（默认1000ms）
→ FC01 单次读 X7（63495）
```

X7=1 成功，X7=0 为 `Rejected`；通信与取消处理同充磁。退磁判据不额外检查 X6 是否为 0。

两种动作共用`App.Crane.MagnetFeedbackDelayMs`，默认1000ms，参数页“天车→编辑→充退磁反馈等待时间(ms)”可改。等待位置在写0完成后；每次动作开始读取并固定本次配置，文件重载后下一动作采用，进行中的动作不变。0表示不额外等待，负数拒绝执行；等待支持取消，取消后不再发起反馈读取。其他手动动作没有新增这个等待。

两种动作都只有一次脉冲和一次反馈读取，**没有三次重试，也没有 3s 反馈轮询**。手动充磁按钮不额外检查 X11，也不自动下降取料。

自动取料另外会先到取料位，等 500ms 后专用读 X11；明确无板才按配置有限补降，默认最多 3 次、每次 5mm，各次补降后再等 500ms 检查。读到有板后才设置“充磁已开始”标志并调用本节充磁方法。该检查属于 `TransferContext`，不属于底层磁铁按钮。

## 10. 急停、中止任务与暂停线路

| 操作 | 对 PLC 的直接操作 | 对自动任务的处理 |
|---|---|---|
| 手动页急停 | D4518=2 → 200ms → 0 | 不自动取消任务令牌、弃板或释放资源 |
| 手动页中止当前任务 | 按钮不下发急停；取消后的运动方法可能继续尝试复位自身触发位 | 只取消所选车当前 TaskId 对应的执行；始终沿用 `TaskAbortCoordinator.Abort` 弃板 |
| 暂停线路 | 本身不直接下发天车 PLC 停止命令 | 阻止后续正常派发；已开始的搬运继续，入口尚未通过的搬运回滚分配 |

“中止当前任务”会立即请求故障暂停并取消本次独享令牌；状态机记录异常、标记工件 `Discarded`、清相关工件内存引用、释放预约/路权、清天车任务并报警。取料是否已经充磁不改变**人工中止**的弃板处理。

它不自动移动天车回安全位，也不统一清 PLC 握手信号。现场负责停止并处理实物，必要时使用设备清握手位入口。Worker 只结束当前搬运，天车消费循环保持存活；后续任务会建立新的令牌，不继承本次手动取消。其他车已在执行的搬运不因这个按钮一起取消。

普通自动流程异常则按充磁边界区分：取料开始调用充磁之前保留源工件并回 Waiting；开始调用之后沿用弃板。手动页普通 PLC 命令失败只反馈操作结果，不自动套用搬运异常协调器。完整说明见[应用层设计](../应用层设计.md)和[手动操作页面](../页面布局/手动操作页面.md)。

## 13. 返回结果、配置与日志

### 13.1 结果码

| 结果码 | 成败 | 当前含义 |
|---|---|---|
| `InPosition` | 成功 | 运动普通到位 |
| `PressureReached` | 成功 | X2 触发且 Z 误差在下压容差内 |

| `PressureOutOfRange` | 失败 | 下压触发，但 Z 超差 |

## 16. 自动搬运的XY一次微调

仅在取料首次到源设备上方成功后、下降之前，以及中转首次到目标设备上方成功后、清握手和释放源资源之前执行。判断位于[TransferContext](../../src/AutomatedLine.Application/Transfer/TransferContext.cs)，复用[CraneService](../../src/AutomatedLine.Infrastructure/Communication/CraneService.cs)现有ReadStatusAsync和MoveRelativeAsync，没有独立微调驱动接口。

普通运动成功后，按App.Crane.XyRefineSettleMs（默认500ms，允许0）等待一次，读取一次绝对编码器。各轴`|目标－编码器|`严格大于App.Crane.XyRefineToleranceMm（默认5mm）时，取`目标－编码器`为相对增量；未超差轴增量0。存在超差则只调用一次MoveRelativeAsync(dx,dy,0)，否则直接继续。

微调下发前还须满足两轴最大距离：App.Crane.XyRefineMaxXCorrectionMm默认200mm、XyRefineMaxYCorrectionMm默认100mm。使用long绝对误差比较，任一轴严格超限就整次不补发并抛异常；不会截成200/100或拆成多次，另一轴即使在范围内也不先动。正负方向一致，等于±200/±100允许。statemachine.txt的超限Error包含目标、编码器、带方向差值、绝对误差、触发阈值、配置上限和超限轴，并说明整次未下发。源侧超限按充磁前保板，目标侧按充磁后弃板及有条件尽力清握手。

目标换算、D3102/D3104写入、D4522/D4521写2保持500ms后写0、Busy和普通到位等待、失败复位均复用原相对运动流程。Z增量0，不写D3106、不触发D4520。补发成功就继续，不再额外读取和验证5mm误差，不追加微调。5mm仅为补发触发阈值；补发运动按现有普通到位容差和运动超时判定成功。读取失败或报警不补发，取消和运动失败沿用原搬运处理。
