# 沈阳斜床协议（FANUC FOCAS 宏变量）



端口 8193    ip用数据库的ip   协议是自定义的fanc协议

## 斜床->上位机  输入信号

| 宏变量 | 内容         |
| ------ | ------------ |
| #1001  | 请求数据     |
| #1002  | 请求上料     |
| #1003  | 尾座夹紧到位 |
| #1004  | 请求下料     |
| #1005  | 尾座分开到位 |

## 上位机->斜床  输出信号

### 3.1 加工参数

| 宏变量 | 内容              | 格式   |
| :----: | ----------------- | ------ |
|  #800  | 版辊长度          | double |
|  #801  | 斜车成活直径      | double |
|  #802  | 堵孔尺寸/版孔类型 | double |
|  #909  | 加工模式          | int    |

### 3.2 握手输出

| 宏变量 | 信号         |
| :----- | :----------- |
| #1101  | 数据下发完成 |
| #1102  | 天车上料到位 |
| #1103  | 天车上料完成 |
| #1104  | 天车下料到位 |
| #1105  | 天车下料完成 |



## 天车与斜床交互



上料：

1. xy到位斜床上方 读请求数据=1
2. 读到了 下发版辊长度 斜车成活直径  堵孔尺寸/版孔类型 加工模式 然后写 数据下发完成=1
3. 写完 读请求上料=1
4. 读到了 z下降到数据库位置
5. z下降到位了 y进行二次移动(z到位才移动) 这个移动距离多少和板孔的大小 还有这个斜床门宽度有关 这是个公式 到时候会给 并且大孔移动多少 小孔移动多少 斜床门多宽 都会给 json会保存   举例：数据库y寸的绝对值编码器坐标可能是200  y二次移动需要移动到100这个位置 
6. y二次移动到位了 发天车上料到位=1
7. 读尾座夹紧到位=1
8. 读到了 放磁 z回升安全位置->发天车上料完成



下料：

1. 注意  上料是xy到位后 y有一个二次移动  下料就是x到位 y到二次移动的这个位置 不是数据库位置了  
2. 移动到位读请求下料=1
3. 读到请求下料=1 z下降
4. 充磁 感应有板信号
5. 下发天车下料到位
6. 读尾座分开到位=1
7. 读到了 y进行二次移动 此时就是y移动到数据库位置了
8. y二次移动到位 z回升到安全位置 发下料完成

这就是一轮完成了
