# 已完成任务自动清理

实现：[CompletedTaskCleanupService](../src/AutomatedLine.Application/Runtime/CompletedTaskCleanupService.cs)、[RuntimeTaskManager](../src/AutomatedLine.Application/Runtime/RuntimeTaskManager.cs)、[WorkpieceRuntime](../src/AutomatedLine.Domain/Workpieces/WorkpieceRuntime.cs)。

## 默认流程

```text
最终下料搬运收尾成功
→ MarkCompleted先记录UTC完成时间，再发布Completed
→ 至少保留60秒
→ 独立后台每10秒检查
→ 清理该工件匹配的设备/天车内存引用
→ 从任务表批量移除
→ 锁外只发送一次Changed，主页面更新列表和数量
→ 同版号、同序号可作为新工件再次接收
```

生成器确认工件已到锁定工艺的下料终点、没有下一工序时，也通过MarkCompleted记录时间。中间工序搬完只是Waiting，不属于自动清理对象。每10秒检查是每轮结束后等待，因此默认删除通常发生在完成60～70秒后，实际还取决于线程及页面响应时间。

## 删除边界与并发

- 只处理状态为Completed、CompletedAtUtc不为空且已达到当前保留期限的工件。Created、Waiting、Assigned、Running、Paused、Discarded全部保留；缺少完成时间的Completed也保留。
- 使用工件唯一Guid匹配引用，工件Guid和天车每趟搬运TaskId不是同一个概念。
- DeviceBase、Crane的CurrentWorkpiece通过Volatile发布。注册表先读对象、核对Guid，再用Interlocked.CompareExchange原子置空；读取后若下料架/天车已换成新对象，清理失败并保留新对象，即使版号序号相同也不会按业务文本删除新引用。
- RuntimeTaskManager在与ERP批量入队共用的任务表锁内筛选、清引用、一次RemoveAll提交删除，避免逐件删除与多次UI刷新。日志和一次Changed都在锁外，通知可重新查询任务表。
- 不下发PLC命令，不清信号快照，不修改天车CurrentTask、状态、路权或预约，不删除配置或磁盘日志，也不代表现场实物被移走。
- UI通知失败记录Warning，已提交的删除不回滚；页面后续节拍发现数量变化可重建列表。后台其他异常记录Warning后继续下一轮，不进入线路故障暂停。

## 后台生命周期与参数

服务通过App.ConfigureServices的AddHostedService注册，只依赖任务表、资源目录、配置、日志与时钟；不依赖主页面、LineControlService或通信驱动。程序宿主运行期间，切换页面、暂停线路、暂停ERP监听均不会停止清理。退出程序时取消当前等待并记录停止日志。

参数位于参数设置页“完成任务清理”，使用原有动态编辑弹框：

| 页面名称 | JSON路径 | 默认值 | 范围 |
|---|---|---:|---|
| 启用自动清理(1开/0关) | App.CompletedTaskCleanup.Enabled | true（页面1） | 1开启，0关闭；其他输入按关闭处理 |
| 完成保留时间(秒) | App.CompletedTaskCleanup.RetentionSeconds | 60 | 非负整数，0表示下一轮即可清理 |
| 检查间隔(秒) | App.CompletedTaskCleanup.CheckIntervalSeconds | 10 | 1～2147483，确保可换算为Int32毫秒 |

每轮捕获一份参数，保存并重载后下一轮采用新值，已开始的等待不改变，无需重启。非法保留/间隔时本轮不删除，记录原因并以默认10秒间隔重试；关闭后保留全部记录，开启后到期记录进入后续清理。源码与Debug运行目录实际appsettings.json分别补缺项，保留各自原值及连接串，不维护Example文件。

## ERP再次接收

删除前仍按现有任务表中的版号+序号拒绝重复；删除后不保留额外已完成身份表。新接收工件生成新RuntimeId、捕获当时最新工艺快照，并以新的QueueOrder追加队尾。

文件里未曾接收、因重复保留的行在旧记录清理后也会自动接收，不要求重新写入文件。已经接收但文件回写失败的行仍由原回执保护，不会因清理而重复提交同一回执。是否接收仍遵守ERP监听开关；自动清理本身不受监听开关影响。

## 日志

实际目录沿用App.Logging.Directory。任务明细在task.txt，服务与批次日志在operation.txt，原任务完成日志保留。

| 场景 | 内容 |
|---|---|
| 服务启动/停止 | 独立于页面和线路状态、只清到期Completed、不操作PLC；宿主退出记录停止 |
| 首轮/参数变化 | 启用状态、保留秒数、检查秒数；非法值记录Warning和重试策略 |
| 每件自动删除 | 版号/序号、工件Guid、完成UTC时间、清理截止时间、实际清除设备/天车引用数量、允许再次接收 |
| 每批完成 | 实际删除数量、截止时间、页面批量通知一次、不保留额外去重记录 |
| 清理或通知异常 | 原因、已提交删除不回滚或本轮重试策略；不改变线路状态 |

没有到期记录时不逐轮刷日志。删除时刻和完成时刻分别记录，便于追溯工件为何从主页面消失。
