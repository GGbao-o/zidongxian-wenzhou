# 配置与运行说明

核对日期：2026-10-08。运行入口：[App.xaml.cs](../src/AutomatedLine.Ui/App.xaml.cs)，参数定义：[AppOptions](../src/AutomatedLine.Application/Configuration/AppOptions.cs)、[TransferOptions](../src/AutomatedLine.Application/Configuration/TransferOptions.cs)。

## 1. 配置文件与依赖

程序以 AppContext.BaseDirectory 为内容根目录；appsettings.json、相对 Logs 目录以输出/运行目录为准，不是启动命令所在目录。UI工程把本地appsettings.json配置为复制输出，示例见 [appsettings.Example.json](../src/AutomatedLine.Ui/appsettings.Example.json)。真实连接串不放入文档。

数据库连接键为ConnectionStrings:MySql，缺失时ConfigService抛配置异常。MySQL只保存CraneConfig、DeviceConfig。EF实体映射不等于启动自动建表；数据库结构需按部署实际维护。FOCAS依赖32位原生库，解决方案x86；部署须具备匹配的.NET运行环境与原生依赖。

## 2. 启动顺序

1. 创建宿主与单例服务。
2. ConfigurationLoader.LoadAsync清资源注册表/驱动注册表及待领取通道，读取启用配置，建领域对象和驱动。车按No、设备按Id装载；驱动通常首次请求才连接。
3. 装载失败记录系统错误和报警，应用仍可能显示UI，不代表资源已齐全。
4. Host.StartAsync启动生成器、调度器、Worker及设备采集。初始线路Stopped。
5. 延时约700ms后冷启动核对，随后显示主窗口；时间延迟不保证全体设备首轮采集完成。
6. 主页面点击启动，再核对现场后将线路置Running。

ColdStartChecker只记录现场有料/有板但无内存引用的Warning，不自动创建工件、隔离车或阻止开线。配置装载异常后的空/部分注册表应结合系统日志确认。App在宿主启动后才订阅报警弹窗事件；此前装载阶段记录的错误保留在活动报警/日志中，不会因为后续订阅自动补弹一次。

## 3. App参数默认值

| 路径（App下） | 默认 | 用途 |
|---|---:|---|
| Collection.DeviceIntervalMs | 500 | 设备采集轮次间等待ms |
| Collection.CommunicationTimeoutMs | 3000 | 设备Modbus单次请求期限ms；非正值工厂兜底3000。天车客户端当前未接此参数，使用默认3000 |
| Scheduling.GenerateIntervalMs | 500 | 候选生成等待ms |
| Scheduling.ScheduleIntervalMs | 500 | 集中调度等待ms |
| Crane.MoveTimeoutMs | 60000 | 每次到位轮询期限ms |
| Crane.PositionToleranceMm | 5 | 正常到位容差mm |
| Crane.PressureToleranceMm | 15 | X2触发后的Z容差mm |
| StateMachine.HandshakeTimeoutMs | 60000 | 设备/天车条件握手等待ms |
| StateMachine.ExecuteIntervalMs | 500 | Worker等待ms |
| Logging.Directory | Logs | 相对程序目录或绝对路径 |
| Logging.RetentionDays | 30 | 按日期清理保留期 |
| Logging.MaxFileSizeBytes | 10485760 | 单文件10MiB滚动 |
| Logging.SampleSeconds | 20 | 高频抽样间隔s，页面没有编辑项 |
| Transfer.Lathes[设备Id].TailstockCenterDistance | 0 | 该斜床顶尖距离 |
| Transfer.Lathes[设备Id].BigHoleOffset | 122 | 堵孔100使用 |
| Transfer.Lathes[设备Id].SmallHoleOffset | 55 | 其他堵孔使用 |

以下仅为App节点示例，斜床参数按现场标定补充；不包含真实数据库信息：

```json
{
  "App": {
    "Collection": { "DeviceIntervalMs": 500, "CommunicationTimeoutMs": 3000 },
    "Scheduling": { "GenerateIntervalMs": 500, "ScheduleIntervalMs": 500 },
    "Crane": { "MoveTimeoutMs": 60000, "PositionToleranceMm": 5, "PressureToleranceMm": 15 },
    "StateMachine": { "HandshakeTimeoutMs": 60000, "ExecuteIntervalMs": 500 },
    "Transfer": { "Lathes": {} },
    "Logging": { "Directory": "Logs", "RetentionDays": 30, "MaxFileSizeBytes": 10485760, "SampleSeconds": 20 }
  }
}
```

Configuration绑定不区分属性大小写；参数页面保存时按ConfigService的camelCase格式写回。Transfer.Lathes键为设备Id，不是排序号或IP。handler缺少对应斜床项时YOffset=0，不使用另一台车/斜床的参数。

## 4. 参数生效时机

| 参数 | 当前读取位置 | 建议确认方式 |
|---|---|---|
| 采集/生成/调度/Worker周期 | 服务启动时 | 重启后确认 |
| 设备Modbus通信期限、天车运动容差/超时 | 驱动构造时 | 重建驱动/重启后确认 |
| 日志配置 | 日志器构造时 | 重启后确认 |
| 握手期限、斜床搬运参数 | 新TransferContext选项 | 新搬运使用当前选项，已有上下文不会可靠切换 |

页面保存成功表示写配置，不是所有服务即时重配置。循环周期最低50ms，实际刷新间隔还加上本轮耗时。取料500ms稳定等待、200ms脉冲、运动500ms脉冲和UI1s节拍目前固定在代码，不是上述可编辑周期。

## 5. 数据库资源配置变更

1. 暂停后等待已经开始的搬运结束，或按异常现场流程完成处理。
2. 在非Running状态修改配置；可走管理页，也可按现场数据库维护方式操作。
3. 管理页保存/删除会装载两类注册表；直接改表不会立即触发装载。此装载不重建Worker、路权、预约及工件运行态，不能当作完整热重启。
4. 完成现场与工件处理后关闭并重新打开程序，核对资源与参数，再建立内存工件并启动线路。

重启不恢复旧列表任务；不要在未处理的实物上仅凭旧日志推断自动恢复成功。Protocol/Port保留在表里，但实际端口/站号由工厂固定，详见[通信说明](通信与点位说明.md)。

## 6. 正常暂停与故障恢复

正常暂停只阻止新任务，当前搬运继续；重新开线继续处理保留的等待或通道任务。单任务Paused只阻止这个工件生成候选，不清设备引用和位置。

充磁调用前故障：记录仍在Waiting、原位置/工序/序号保留。完成现场确认后启动线路，可再生成同一工件任务；不需要人工删除再建。

充磁调用开始后故障：原工件Discarded，内存引用清理、车Idle、资源释放、线路故障暂停。现场人工取走实物并使车回安全位置，按需在手动页清PLC报警/握手，再启动线路，车可执行其他符合调度条件的工件。主页面可保留弃板记录追溯，也可删除记录。

清活动报警列表、关闭错误弹窗和点PLC清报警都不是重新启动线路。异常协调器本身没有回安全位或清握手写入。

## 7. 关闭与日志

退出应用停止宿主并释放；真正宿主取消按取料阶段清理并退出车循环。线路启动不会重建已退出的宿主循环。

日志目录按本地日期 yyyy-MM-dd，文件名为类别小写：system、communication、collection、generation、scheduling、statemachine、task、alarm、operation，扩展名.txt。文件超限滚为带HHmmss的历史文件；按保留期清日期目录。活动报警清空不删除这些文件。
