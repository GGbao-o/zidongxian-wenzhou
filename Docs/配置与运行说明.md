# 配置与运行说明

核对日期：2026-10-13。运行入口：[App.xaml.cs](../src/AutomatedLine.Ui/App.xaml.cs)，参数定义：[AppOptions](../src/AutomatedLine.Application/Configuration/AppOptions.cs)、[TransferOptions](../src/AutomatedLine.Application/Configuration/TransferOptions.cs)。

## 1. 配置文件与依赖

程序以 AppContext.BaseDirectory 为内容根目录；appsettings.json、相对 Logs 目录以输出/运行目录为准，不是启动命令所在目录。UI工程把本地appsettings.json配置为复制输出，示例见 [appsettings.Example.json](../src/AutomatedLine.Ui/appsettings.Example.json)。真实连接串不放入文档。

数据库连接键为ConnectionStrings:MySql，缺失时ConfigService抛配置异常。MySQL只保存CraneConfig、DeviceConfig。EF实体映射不等于启动自动建表；数据库结构需按部署实际维护。FOCAS依赖32位原生库，解决方案x86；部署须具备匹配的.NET运行环境与原生依赖。

数据库注册使用 `ServerVersion.AutoDetect(connectionString)` 探测实际服务器版本，没有在源码固定一个MySQL服务版本。客户端/EF包版本不能当作远程服务器版本；部署Windows服务器应按实际数据库兼容环境建立服务并配置连接，本文不声称已经安装或核实了远程数据库。

## 2. 启动顺序

1. 创建宿主与单例服务。
2. ConfigurationLoader.LoadAsync清资源注册表/驱动注册表及待领取通道，读取启用配置，建领域对象和驱动。车按No、设备按Id装载；驱动通常首次请求才连接。
3. 装载失败记录系统错误和报警，应用仍可能显示UI，不代表资源已齐全。
4. Host.StartAsync启动天车采集、生成器、调度器、Worker及设备采集。初始线路Stopped。
5. 延时约700ms后冷启动核对，随后显示主窗口；时间延迟不保证全体设备首轮采集完成；天车部分另并发有界等待有效且X11已知的共享快照。
6. 主页面点击启动，再核对现场后将线路置Running。

ColdStartChecker只记录现场有料/有板但无内存引用的Warning，不自动创建工件、隔离车或阻止开线。配置装载异常后的空/部分注册表应结合系统日志确认。App在宿主启动后才订阅报警弹窗事件；此前装载阶段记录的错误保留在活动报警/日志中，不会因为后续订阅自动补弹一次。

冷启动检查也会在每次从Paused/PausedByFault恢复线路时执行，并不限于任务表为空。设备缺采集快照就跳过；启用天车等已知X11的有效缓存，默认各车并发最多等3000ms，超时只记“核对未完成”，随后仍启动。已发现残留时新增Warning活动报警及alarm日志，不弹线路Error错误框，不给该车设置禁止后续任务的状态。

## 3. App参数默认值

| 路径（App下） | 默认 | 用途 |
|---|---:|---|
| Collection.DeviceIntervalMs | 500 | 设备采集轮次间等待ms |
| Collection.CraneIntervalMs | 500 | 每车独立采集轮次间等待ms，不重叠，单车读完立即发布 |
| Collection.CraneSnapshotMaxAgeMs | 2000 | 从读取开始算的最大有效年龄ms；过期不展示为有效状态、不参与选车 |
| Collection.CommunicationTimeoutMs | 3000 | 设备Modbus单次请求期限ms；非正值工厂兜底3000。天车客户端仍使用默认3000；本参数也用于冷启动等待有效天车缓存的期限 |
| Scheduling.GenerateIntervalMs | 500 | 候选生成等待ms |
| Scheduling.ScheduleIntervalMs | 500 | 集中调度等待ms |
| Crane.MoveTimeoutMs | 60000 | 每次到位轮询期限ms |
| Crane.PositionToleranceMm | 5 | 正常到位容差mm |
| Crane.PressureToleranceMm | 15 | X2触发后的Z容差mm |
| StateMachine.HandshakeTimeoutMs | 60000 | 设备/天车条件握手等待ms |
| StateMachine.ExecuteIntervalMs | 500 | Worker等待ms |
| StateMachine.PickPlateRetryCount | 3 | 取料原位X11明确无板后的追加下降次数，0关闭，不能负值 |
| StateMachine.PickPlateStepMm | 5 | 每次仅Z相对下降的指令距离mm，必须正整数 |
| Logging.Directory | Logs | 相对程序目录或绝对路径 |
| Logging.RetentionDays | 30 | 按日期清理保留期 |
| Logging.MaxFileSizeBytes | 10485760 | 源码默认单文件10MiB滚动；现场JSON可覆盖 |
| Logging.SampleSeconds | 20 | 高频抽样间隔s，页面没有编辑项 |
| Transfer.Lathes[设备Id].TailstockCenterDistance | 0 | 该斜床顶尖距离 |
| Transfer.Lathes[设备Id].BigHoleOffset | 122 | 堵孔100使用 |
| Transfer.Lathes[设备Id].SmallHoleOffset | 55 | 其他堵孔使用 |

以下仅为App节点示例，斜床参数按现场标定补充；不包含真实数据库信息：

```json
{
  "App": {
    "Collection": { "DeviceIntervalMs": 500, "CraneIntervalMs": 500, "CraneSnapshotMaxAgeMs": 2000, "CommunicationTimeoutMs": 3000 },
    "Scheduling": { "GenerateIntervalMs": 500, "ScheduleIntervalMs": 500 },
    "Crane": { "MoveTimeoutMs": 60000, "PositionToleranceMm": 5, "PressureToleranceMm": 15 },
    "StateMachine": { "HandshakeTimeoutMs": 60000, "ExecuteIntervalMs": 500, "PickPlateRetryCount": 3, "PickPlateStepMm": 5 },
    "Transfer": { "Lathes": {} },
    "Logging": { "Directory": "Logs", "RetentionDays": 30, "MaxFileSizeBytes": 10485760, "SampleSeconds": 20 }
  }
}
```

Configuration绑定不区分属性大小写；参数页面保存时按ConfigService的camelCase格式写回。Transfer.Lathes键为设备Id，不是排序号或IP。handler缺少对应斜床项时YOffset=0，不使用另一台车/斜床的参数。

默认值以AppOptions为准，示例也使用10MiB日志上限。现场若配置104857600则实际使用100MiB，属于覆盖值而非源码默认。新增两项天车配置已接入[参数页面](页面布局/参数设置页面.md)“采集 → 编辑”；XAML按参数列表动态生成控件。已有JSON缺字段用默认值，确认保存会写入App；更新示例配置不等于替服务器改好了运行文件。

## 4. 参数生效时机

| 参数 | 当前读取位置 | 建议确认方式 |
|---|---|---|
| 设备/天车采集、生成、调度、Worker周期 | 服务启动时 | 重启后确认 |
| 天车快照最大年龄 | 每次缓存查询 | 写盘并被IConfiguration自动重载后，后续查询采用新值 |
| 冷启动缓存等待上限 | 每次启动核对 | 取当前Collection.CommunicationTimeoutMs，最低50ms |
| 设备Modbus通信期限、天车运动容差/超时 | 驱动构造时 | 重建驱动/重启后确认 |
| 日志配置 | 日志器构造时 | 重启后确认 |
| 握手期限、斜床搬运参数 | 新TransferContext选项 | 新搬运使用当前选项，已有上下文不会可靠切换 |
| 取料补降次数/单步距离 | 新TransferContext选项，每次取料检查开始取值 | 文件保存重载后新搬运使用，不改变已经进行中的补降配置 |

页面保存成功表示写配置，不是所有服务即时重配置。循环周期最低50ms，实际刷新间隔还加上本轮耗时。取料原位及每次补降后的500ms稳定等待、200ms脉冲、运动500ms脉冲和UI1s节拍目前固定在代码；补降次数/单步距离可在“参数设置 → 状态机 → 编辑”修改。

默认补降是原位读一次加最多3次×5mm，共最多4次专用X11读取、15mm累计指令下降；次数不含原位检查。计数和距离非法时充磁前失败，不静默套回默认值。示例JSON已更新，旧运行文件缺这两项使用默认值，参数页整体保存后写入；实际私有配置文件未被替换。

后台采集更新缓存、页面每1s应用缓存、PropertyChanged更新WPF是三个环节。后台发布不会直接刷新本页属性，调快采集不改变UI固定节拍；手动页选中天车后自动更新，无需反复点击刷新。采集失败或过期时两个页面按各自不可用样式显示，手动页清旧值为“—”，大屏坐标沿用默认0及红框。

## 5. 数据库资源配置变更

1. 暂停后等待已经开始的搬运结束，或按异常现场流程完成处理。
2. 在非Running状态修改配置；可走管理页，也可按现场数据库维护方式操作。
3. 管理页保存/删除会装载两类注册表；直接改表不会立即触发装载。此装载不重建Worker、路权、预约及工件运行态，不能当作完整热重启。
4. 完成现场与工件处理后关闭并重新打开程序，核对资源与参数，再建立内存工件并启动线路。

重启不恢复旧列表任务；不要在未处理的实物上仅凭旧日志推断自动恢复成功。Protocol/Port保留在表里，但实际端口/站号由工厂固定，详见[通信说明](通信与点位说明.md)。

## 6. 正常暂停与故障恢复

正常暂停只阻止新任务，当前搬运继续；重新开线继续处理保留的等待或通道任务。单任务Paused只阻止这个工件生成候选，不清设备引用和位置。

线路状态使用volatile字段供多线程读取；RunFlowAsync在获取资源和写PLC前再判断一次。若任务刚出队但入口发现未运行、且未收到人工/宿主取消，则回滚本次分配：工件回Waiting，源/目标设备引用和信号不变，位置/工序/QueueOrder保留，天车任务与区间清空、Idle；只记回滚日志，不变成故障暂停、不弹异常框。恢复后该工件仍可生成候选，尚未领取的通道任务不清空。

候选池由生成器下一轮发现未运行时清空，不是Pause方法同步清除。调度器已进入的一轮仍可能入队，Worker读取运行状态与出队也不是原子操作；入口检查补挡未开始的搬运，不自动终止已经通过入口的流程。

充磁调用前故障：记录仍在Waiting、原位置/工序/序号保留。完成现场确认后启动线路，可再生成同一工件任务；不需要人工删除再建。

充磁调用开始后故障：原工件Discarded，内存引用清理、车Idle、资源释放、线路故障暂停。现场人工取走实物并使车回安全位置，按需在手动页清PLC报警/握手，再启动线路，车可执行其他符合调度条件的工件。主页面可保留弃板记录追溯，也可删除记录。

清活动报警列表、关闭错误弹窗和点PLC清报警都不是重新启动线路。异常协调器本身没有回安全位或清握手写入。

人工中止仅针对所选天车已领取的当前任务，无论充磁前后都弃板；它与普通充磁前故障保留工件不同。不下发自动急停，现场负责停止/取板/安全位置确认。当前执行令牌关联宿主，所以宿主停止也能取消此任务；人工中止不会取消宿主或以后新任务的令牌。详细判断见[应用层取消说明](应用层设计.md#511-两层取消判断与重复清理)。

搬运Error报警弹出“线路异常（已暂停）”，正文为异常详情、来源/资源、系统动作和秒级时间，错误图标、确定按钮。最新保留/弃板提示包含现场信号与安全位置确认，完整原文及其他提示框见[报警页面](页面布局/报警处理页面.md)。

## 7. 关闭与日志

天车采集collection日志记录启动/停止、首次成功、失败与恢复，持续结果抽样；冷启动有效快照超时写system核对未完成。架构与四处消费规则见[天车状态采集设计](天车状态采集设计.md)。

取料补降日志在statemachine.txt：按天车、板号/序号记录检查序号、X11、已完成补降/上限、单次/累计指令距离和实时显示/编码器坐标；失败时列阶段、最后已读位置和真实原因。诊断坐标不可用记未知，不能拿缓存或零代替。具体顺序和日志样例见[应用层补降说明](应用层设计.md#541-取料无板的有限补降与日志)。

退出应用停止宿主并释放；真正宿主取消按取料阶段清理并退出车循环。线路启动不会重建已退出的宿主循环。

日志目录按本地日期 yyyy-MM-dd，文件名为类别小写：system、communication、collection、generation、scheduling、statemachine、task、alarm、operation，扩展名.txt。文件超限滚为带HHmmss的历史文件；按保留期清日期目录。活动报警清空不删除这些文件。

```powershell
dotnet build AutomatedLine.sln --no-restore --nologo -m:1 -p:UseSharedCompilation=false
dotnet test tests/AutomatedLine.Tests/AutomatedLine.Tests.csproj --no-build --no-restore --nologo
```

这些命令用于仓库构建与本机测试，不等于现场PLC、MySQL、FOCAS实机联调完成。文档更新不需要访问现场设备。
