# 配置与运行说明

核对日期：2026-10-19。运行入口：[App.xaml.cs](../src/AutomatedLine.Ui/App.xaml.cs)，参数定义：[AppOptions](../src/AutomatedLine.Application/Configuration/AppOptions.cs)、[TransferOptions](../src/AutomatedLine.Application/Configuration/TransferOptions.cs)。

## 1. 配置文件与依赖

程序以 AppContext.BaseDirectory 为内容根目录；appsettings.json、相对 Logs 目录以输出/运行目录为准，不是启动命令所在目录。直接维护[源码目录实际配置](../src/AutomatedLine.Ui/appsettings.json)及程序运行目录appsettings.json；UI工程按PreserveNewest复制实际配置到输出。已移除额外的example文件和复制项目，不再另维护一套模板。真实配置含连接串，仍不提交Git，连接串也不放入文档。补字段时依据AppOptions/TransferOptions，只填缺失项，保留原有连接串、参数和未知节点。

数据库连接键为ConnectionStrings:MySql，缺失时ConfigService抛配置异常。MySQL只保存CraneConfig、DeviceConfig。EF实体映射不等于启动自动建表；数据库结构需按部署实际维护。FOCAS依赖32位原生库，解决方案x86；部署须具备匹配的.NET运行环境与原生依赖。

数据库注册使用 `ServerVersion.AutoDetect(connectionString)` 探测实际服务器版本，没有在源码固定一个MySQL服务版本。客户端/EF包版本不能当作远程服务器版本；部署Windows服务器应按实际数据库兼容环境建立服务并配置连接，本文不声称已经安装或核实了远程数据库。

## 2. 启动顺序

1. 创建宿主与单例服务。
2. ConfigurationLoader.LoadAsync清资源注册表/驱动注册表及待领取通道，读取启用配置，建领域对象和驱动。车按No、设备按Id装载；驱动通常首次请求才连接。
3. 装载失败记录系统错误和报警，应用仍可能显示UI，不代表资源已齐全。
4. Host.StartAsync启动ERP接收宿主、天车采集、生成器、调度器、Worker及设备采集。初始线路Stopped，ERP默认持续监听，合法任务按文件行序自动启动入队为Waiting；主页面可暂停或恢复监听。实际生成、派发及搬运仍须启动线路并满足设备条件。
5. 延时约700ms后冷启动核对，随后显示主窗口；时间延迟不保证全体设备首轮采集完成；天车部分另并发有界等待有效且X11已知的共享快照。
6. 主页面点击启动，再核对现场后将线路置Running。

ColdStartChecker只记录现场有料/有板但无内存引用的Warning，不自动创建工件、隔离车或阻止开线。配置装载异常后的空/部分注册表应结合系统日志确认。App在宿主启动后才订阅报警弹窗事件；此前装载阶段记录的错误保留在活动报警/日志中，不会因为后续订阅自动补弹一次。

冷启动检查也会在每次从Paused/PausedByFault恢复线路时执行，并不限于任务表为空。设备缺采集快照就跳过；启用天车等已知X11的有效缓存，默认各车并发最多等3000ms，超时只记“核对未完成”，随后仍启动。已发现残留时新增Warning活动报警及alarm日志，不弹线路Error错误框，不给该车设置禁止后续任务的状态。

## 4. 参数生效时机

### 4.1. 保存、重载与业务取值

参数页点击“编辑 → 确定”后，[ParamsViewModel.OpenCategory](../src/AutomatedLine.Ui/ViewModels/ParamsViewModel.cs)调用[ConfigService.SaveAppOptions](../src/AutomatedLine.Infrastructure/Config/ConfigService.cs)，写入`AppContext.BaseDirectory/appsettings.json`的`App`节点，保留连接串等其他节点。调试运行通常对应`src/AutomatedLine.Ui/bin/Debug/net8.0-windows/appsettings.json`；发布后对应exe同目录的文件。不会同步修改源码目录的实际配置；两份配置已有参数不同时，补字段应分别保留各自数值。

[App.OnStartup](../src/AutomatedLine.Ui/App.xaml.cs)使用`Host.CreateApplicationBuilder`的默认配置加载行为，保留文件变化自动重载。ConfigService保存时使用同目录临时文件原子替换，并主动同步Reload，成功返回后下一次GetAppOptions即可读取新值；外部直接编辑JSON仍经过文件变化监听。IConfiguration引用不需要重新赋值。

`GetAppOptions()`执行`_configuration.GetSection("App").Get<AppOptions>()`，每次根据当前内存配置创建新参数对象，不直接读磁盘，也不修改已返回对象、局部变量或驱动字段。普通参数保存保留磁盘已有processPlan节点；工序页只局部保存App.processPlan，其他App参数及连接串保持。自动重载针对宿主加载的运行目录文件，源码目录或其他JSON不会自动同步到运行程序。

```text
页面确定/工序勾选 → 局部合并配置 → 原子替换文件并同步重载IConfiguration
                                             ↓
                        下次GetAppOptions创建新的AppOptions对象
                                             ↓
                        重新获取参数的业务使用新值；已有变量保持原值
```

### 4.3. 运行中修改的边界

线路运行中可以保存参数，是否采用新值按上表判断；正常“暂停线路 → 启动线路”只切换线路状态，不重新建立上述后台循环或驱动，不能代替重启程序。驱动重建仅说明该驱动会重新读取参数，不代表资源装载是完整热重启；数据库资源变更仍按第5节处理。

例如，候选生成器的`RunAsync()`是一个长期运行的方法，`var interval = GetAppOptions().Scheduling.GenerateIntervalMs`在`while`之前只执行一次；不是每轮重新调用`RunAsync()`。后续`Task.Delay(interval)`沿用原值，即使此时重新调用`GetAppOptions()`能够得到新值，也不会自动修改已有的`interval`。

页面保存成功表示写配置，不是所有服务即时重配置。循环周期最低50ms，实际刷新间隔还加上本轮耗时。取料原位及每次补降后的500ms稳定等待、所有常规动作（含充退磁）200ms脉冲、运动500ms脉冲和UI1s节拍目前固定在代码；补降次数/单步距离可在“参数设置 → 状态机 → 编辑”修改。充退磁脉冲复位后、单读反馈前的等待已配置为App.Crane.MagnetFeedbackDelayMs，默认1000ms，在“天车 → 编辑”修改；每次动作开始取新值，重载后下一次动作采用，0可取消额外等待，负值在任何PLC写入前拒绝。

默认补降是原位读一次加最多3次×5mm，共最多4次专用X11读取、15mm累计指令下降；次数不含原位检查。计数和距离非法时充磁前失败，不静默套回默认值。本文JSON片段包含这些参数；不维护单独的Example配置文件。旧运行文件缺补降或充退磁反馈等待字段时使用类型默认值，参数页整体保存后写入运行目录的App节点；维护源码目录及运行目录的实际JSON时，分别保留各自已有参数和连接串。

后台采集更新缓存、页面每1s应用缓存、PropertyChanged更新WPF是三个环节。后台发布不会直接刷新本页属性，调快采集不改变UI固定节拍；手动页选中天车后自动更新，无需反复点击刷新。采集失败或过期时两个页面按各自不可用样式显示，手动页清旧值为“—”，大屏坐标沿用默认0及红框。

## 5. 数据库资源配置变更

工艺开关无需修改设备数据库：在工序页勾选/取消，保存后弹出最新完整路线。上下料固定；有启用设备且已实现的加工工序默认参与，动平衡/验点尚未实现，灰显且不进入新路线。EnabledProcesses存放预设选择；无启用设备的加工工序不进入首次捕获路线，离线则仍保留。新路线缺少上下料启用设备时拒绝首次启动，已锁定路线后来缺设备时只等待，不跳过。每件快照仅内存保存，进程重启不恢复旧工件。

1. 暂停后等待已经开始的搬运结束，或按异常现场流程完成处理。
2. 在非Running状态修改配置；可走管理页，也可按现场数据库维护方式操作。
3. 管理页保存/删除会装载两类注册表；直接改表不会立即触发装载。此装载不重建Worker、路权、预约及工件运行态，不能当作完整热重启。
4. 完成现场与工件处理后关闭并重新打开程序，核对资源与参数，再建立内存工件并启动线路。

重启不恢复旧列表任务；不要在未处理的实物上仅凭旧日志推断自动恢复成功。Protocol/Port保留在表里，但实际端口/站号由工厂固定，详见[通信说明](通信与点位说明.md)。

## 6. 正常暂停与故障恢复

斜床通信由Application层DeviceStateCollector持续后台采集，不依赖线路Running。连接失败或读宏失败时仅放弃本轮，发布断开/Bad/空信号快照，等待本轮采集结束及配置的轮间等待后，下轮继续尝试。EW_SOCKET(-16)后通道会释放失效句柄并清连接标志，下一请求重新连接；网络或CNC服务仍不可用时仍会失败，完整读取成功才恢复有效状态。通常无需为短暂断线重启采集器；此通信恢复不自动解除搬运故障暂停，也不重发失败的写宏。端口仍为8193，FOCAS连接/操作超时仍为3秒，无需新增JSON参数，详见[通信恢复说明](通信与点位说明.md#3-focas-通道)。

正常暂停只阻止新任务，当前搬运继续；重新开线继续处理保留的等待或通道任务。单任务Paused只阻止这个工件生成候选，不清设备引用和位置。

线路状态使用volatile字段供多线程读取；RunFlowAsync在获取资源和写PLC前再判断一次。若任务刚出队但入口发现未运行、且未收到人工/宿主取消，则回滚本次分配：工件回Waiting，源/目标设备引用和信号不变，位置/工序/QueueOrder保留，天车任务与区间清空、Idle；只记回滚日志，不变成故障暂停、不弹异常框。恢复后该工件仍可生成候选，尚未领取的通道任务不清空。

候选池由生成器下一轮发现未运行时清空，不是Pause方法同步清除。调度器已进入的一轮仍可能入队，Worker读取运行状态与出队也不是原子操作；入口检查补挡未开始的搬运，不自动终止已经通过入口的流程。

充磁调用前故障：记录仍在Waiting、原位置/工序/序号保留。完成现场确认后启动线路，可再生成同一工件任务；不需要人工删除再建。

充磁调用开始后故障：原工件Discarded，内存引用清理、车Idle、资源释放、线路故障暂停。现场人工取走实物并使车回安全位置，按需在手动页清PLC报警/握手，再启动线路，车可执行其他符合调度条件的工件。主页面可保留弃板记录追溯，也可删除记录。

清活动报警列表、关闭错误弹窗和点PLC清报警都不是重新启动线路。异常协调器本身没有回安全位或清握手写入。

人工中止仅针对所选天车已领取的当前任务，无论充磁前后都弃板；它与普通充磁前故障保留工件不同。不下发自动急停，现场负责停止/取板/安全位置确认。当前执行令牌关联宿主，所以宿主停止也能取消此任务；人工中止不会取消宿主或以后新任务的令牌。详细判断见[应用层取消说明](应用层设计.md#511-两层取消判断与重复清理)。

搬运Error报警弹出“线路异常（已暂停）”，正文为异常详情、来源/资源、系统动作和秒级时间，错误图标、确定按钮。最新保留/弃板提示包含现场信号与安全位置确认，完整原文及其他提示框见[报警页面](页面布局/报警处理页面.md)。

## 7. 关闭与日志

搬运逐步日志分为三层：statemachine记录完整搬运Id/工件Id、工件参数、设备坐标与天车偏移、速度指令、运动/写入返回和等待条件；operation记录天车实际目标换算、寄存器触发/复位、位置误差及Busy、充退磁单次反馈；communication记录设备FC/宏地址、倍率、实际Word及打印内容编码。握手等待记录原值、快照序号/时间/年龄、期望、满足/超时和耗时，首次及状态变化立即记录，无变化每2秒记录进度；运动等待在首次、Busy变化及每2秒记录本轮实测值。日志复用原请求结果，不新增PLC读取、写入或业务延时；详见[应用层日志说明](应用层设计.md#11-日志查找)。

天车采集collection日志记录启动/停止、首次成功、失败与恢复，持续结果抽样；冷启动有效快照超时写system核对未完成。架构与四处消费规则见[天车状态采集设计](天车状态采集设计.md)。

取料补降日志在statemachine.txt：按天车、板号/序号记录检查序号、X11、已完成补降/上限、单次/累计指令距离和实时显示/编码器坐标；失败时列阶段、最后已读位置和真实原因。诊断坐标不可用记未知，不能拿缓存或零代替。具体顺序和日志样例见[应用层补降说明](应用层设计.md#541-取料无板的有限补降与日志)。

点击主窗口右上角关闭按钮或按 Alt+F4，弹出“关闭程序”确认框，正文为“确定要关闭程序吗？”，提供“确定”和“取消”。默认选择取消；取消或关闭确认框会保留主窗口，不停止宿主、不改变线路运行状态。选择确定后按原退出流程关闭程序。

退出应用停止宿主并释放；真正宿主取消按取料阶段清理并退出车循环。线路启动不会重建已退出的宿主循环。

日志目录按本地日期 yyyy-MM-dd，文件名为类别小写：system、communication、collection、generation、scheduling、statemachine、task、alarm、operation，扩展名.txt。文件超限滚为带HHmmss的历史文件；按保留期清日期目录。活动报警清空不删除这些文件。
