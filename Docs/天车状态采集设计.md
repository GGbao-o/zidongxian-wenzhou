# 天车共享状态采集

核对日期：2026-10-10。本文说明 Application 共享采集的职责、有效性和四处消费边界。

## 1. 依赖与数据流

`CraneStateCollector → ICraneDriver.ReadStatusAsync → CraneStateStore → ICraneStateProvider → 消费者`。

- Infrastructure 驱动负责 Modbus 通信、点位解析和即时动作确认。
- Application 的 [CraneStateCollector](../src/AutomatedLine.Application/Collection/CraneStateCollector.cs) 是宿主后台服务，每台启用天车一个串行采集循环。
- [CraneStateStore](../src/AutomatedLine.Application/Collection/CraneStateStore.cs) 是全线唯一缓存，整体发布不可变 [CraneStateSnapshot](../src/AutomatedLine.Application/Collection/CraneStateSnapshot.cs)。
- [ICraneStateProvider](../src/AutomatedLine.Application/Collection/ICraneStateProvider.cs) 只读，不会因查询发起 PLC 请求。
- PLC 数据沿用 CraneStatusDto；任务、工件、路权、程序空闲状态仍读取原 Runtime 和内存引用。两个页面分别维护自己的 ViewModel，不共享页面对象。

缓存属于 Application，不让 Domain 反向依赖 Application DTO，也不把采集字段混入 Crane.Runtime。

## 2. 后台生命周期与发布

App 先装载配置，再启动宿主。采集服务与线路 Running/Paused 无关，宿主存活时持续工作。

监督循环按当前启用天车目录创建采集循环，观察已结束任务；同一车只有一个循环。每车完成读取后立即发布自己的结果，再等待 CraneIntervalMs；不等待其他车完成，不积压下一轮。新增车辆下一监督轮被发现；移除或停用后循环退出；驱动替换后后续轮次使用新驱动。

单车失败发布 Status=null，并继续下一轮。停止宿主取消采集、等待各车循环结束并观察异常，再记录停止日志。共享采集跟随目录变化不代表 Worker、路权及工件已经完整热重建；数据库资源变更仍按[配置说明](配置与运行说明.md)处理。

完整读取包含两次寄存器读取和九次线圈读取，共 11 次请求。各车连接独立；同一车的采集与即时运动读取仍共用驱动连接及通信锁，后台采集不能保证硬实时命令优先级。

## 3. 快照与有效性

| 字段/查询 | 含义 |
|---|---|
| CraneId、Sequence | 归属与全局递增结果序号，失败也递增 |
| ReadStartedAt | 整轮开始读取时间；点位分多次请求，不保证 PLC 全部字段同时取值 |
| CollectedAt | 整轮读取结束并发布时间，用于诊断耗时 |
| Status | 本次 PLC 状态；整次失败为 null，单个线圈未知保留 bool? 的 null |
| FailureReason | 整次失败原因，不回退到上一轮正常结果 |
| GetSnapshot | 当前驱动最近结果，用于诊断；不保证未过期 |
| GetFreshStatus | 只返回当前启用车、当前驱动、有状态且未过期的结果 |

时效从**读取开始**的单调时间戳计算，最大年龄默认 2000ms。Windows 校时不会改变年龄判断；读取耗时本身超过最大年龄时，读完也不能作为新鲜数据使用。查询时没有首次结果、失败、过期、停用或驱动身份变化，均返回 null。

旧驱动在配置重载后迟到的结果不能供新车使用；发布与更新重试也核对驱动身份，避免覆盖新驱动的结果。

## 4. 四处消费规则

| 消费者 | 当前行为 |
|---|---|
| 大屏 | RuntimeTicker 约每秒读取有效缓存并更新卡片；整轮入口仍保留防重入。查询无通信等待，失败/过期沿用红框及不可用状态展示 |
| 手动操作页 | 选择天车立即更新，每秒继续更新；刷新按钮仅重新应用缓存。切车或失效时坐标、速度、报警、回原点清为未知，X 信号显示“—”；自动更新不覆盖操作结果 Message |
| 调度 | 候选池非空时为启用且空闲车辆整理有效缓存字典，多个候选复用；无快照、失败、过期或报警车辆不派发。本轮查询不请求 PLC |
| 冷启动 | 各车并发有界等待有效且 X11 已知的缓存，最多 Collection.CommunicationTimeoutMs（默认 3000ms）；成功后沿用残留板 Warning，超时记录该车核对未完成，不当作无板，不新增启动阻塞 |

冷启动每次启动核对都使用相同规则；设备部分仍读取原 Device.Signals。返回空残留列表不代表所有不可用车辆已经核对成功，应结合系统日志查看。

## 5. 即时动作边界

运动前坐标换算、运动到位轮询、下压 X2、充退磁命令后 X6/X7、取料到位并等待 500ms 后的单次 X11 都保持原驱动即时读取。普通故障按取料充磁边界分流、人工中止弃板、资源释放和线路暂停策略没有因缓存改动。

TransferContext.WaitCraneAsync 当前只有定义，没有调用；保留原实时读取实现。IManualOperationService.ReadStatusAsync 仍是即时读取接口，当前手动页面状态展示已不调用它。

## 6. 配置与日志

| 参数 | 默认值 | 生效 |
|---|---:|---|
| Collection.CraneIntervalMs | 500ms | 服务启动读取，最低 50ms；实际间隔包含读取耗时，调整后重启 |
| Collection.CraneSnapshotMaxAgeMs | 2000ms | 每次缓存查询读取，最低 50ms；应大于正常读取耗时及轮间等待 |
| Collection.CommunicationTimeoutMs | 3000ms | 本方案用于冷启动缓存等待上限；天车客户端单次通信仍使用原默认 3000ms |

采集日志写 collection：服务启动/停止、单车首次成功、失败及恢复；连续同类结果使用 Sample 节流。调度拒绝原因写 scheduling，明确状态不可用（未采集/失败/过期）。冷启动未完成写 system，现场残留仍由原 alarm 记录。

## 7. 本机验证

CraneStateCollectionTests 覆盖失败覆盖旧成功、单调时钟时效、迟到驱动隔离、慢车不阻塞其他车、不重入、采集恢复与停止、新增和替换驱动、调度拒绝不可用缓存、冷启动已知 X11/并发等待/取消/过期。现有 Worker 恢复测试接入真实采集服务。

本机 WPF 验证两个页面共用缓存、按秒通知、切车清空、过期未知、刷新按钮不读 PLC 和自动刷新保留 Message。上述验证不连接现场 PLC。
