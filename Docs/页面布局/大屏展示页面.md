# 大屏展示页面（只读）

> 展示现场信号与内存数据，不提供控制按钮。本文以当前 `ScreenPageView` / `ScreenViewModel` 实现为准，更新于 2026-10-10。

## 1. 页面布局与顶部统计

页面从上到下依次是标题与说明、两个应用服务统计卡片、设备卡片组、天车卡片组。
设备按设备号排序，天车按序号排序；每组横向展开，超出可视区域时通过横向滚动查看，页面内容较高时可纵向滚动。
卡片来自注册表，`ConfigurationLoader` 只装载数据库启用的设备与天车。

| 顶部卡片 | 数量来源 | 悬浮框每行内容 |
|---|---|---|
| 候选任务（TransportTaskGenerator） | 当前候选任务池数量 | `版号/序号  源设备→目标设备  优先级数字` |
| 已派发任务（集中调度） | `Runtime.CurrentTask != null` 的天车数量 | `天车名称  版号/序号  源设备→目标设备  天车状态` |

没有内容时分别显示“无候选任务”“无已派发任务”。已派发详情中的工件查不到时显示 `?`。
已派发数量统计已进入天车当前运行态的任务，不包括尚在 Worker 通道等待取出的任务。

## 2. 设备卡片

### 2.1 卡面与数据来源

卡面依次显示设备名称、设备类型、加工状态（空闲/加工中）。工件资料和点位信号放在悬浮框。

- **加工状态**：设备内存 `CurrentWorkpiece` 非空时显示“加工中”，为空时显示“空闲”。这行表示内存在制情况，未使用 PLC 的 `Machining` / `Busy` / `Running` 判断；即使设备断开，内存仍有工件时也会显示“加工中”。
- **工件资料**：上料架使用 `ScreenViewModel` 传入的队头，即位置为 `Queue`、状态为 `Waiting` 且 `QueueOrder` 最小的工件；其余设备使用 `device.CurrentWorkpiece`。未启动/暂停工件不入队，队头规则见[主页面](主页面.md) §4。
- **队头刷新**：`DeviceRowViewModel.Refresh` 选定的同一份工件信息同时用于列表与悬浮详情。队头更换时更新版号、序号和尺寸；无队头且设备自身无工件时显示“当前工件：无”，不保留上一块板的资料。
- 上料架队头仅用于工件资料展示，不会使卡面变成“加工中”。

### 2.2 悬浮框逐行布局

| 行 | 显示内容 | 含义 |
|---|---|---|
| 1 | `设备名称（设备类型）` | 名称与类型 |
| 2 | `连接：已连接/未连接    状态：加工中/空闲` | 最近采集的连接状态，以及内存在制情况 |
| 3 | `当前工件：` | 有工件时的资料标题；无工件时直接显示 `当前工件：无` |
| 4（有工件） | `版号：…  序号：…` | 工件身份 |
| 5（有工件） | `长度：…  直径：…` | 尺寸最多保留三位小数 |
| 随后 | `点位信号：` | 点位区域标题；快照缺失或为空时同一行显示 `点位信号：无数据` |
| 后续每行 | `中文点位名=值` | 遍历采集缓存 `device.Signals.Values`，按英文点位名以 `StringComparer.Ordinal` 排序 |

布尔值显示 `1/0`，空值显示 `-`，浮点数最多保留三位小数；未知点位名原样显示。
工件仅展示版号、序号、长度、直径，其他工艺参数没有放入悬浮框。
各设备的实际点位见第 6 节；斜床缓存同时包含机床输入和上位机握手输出的读回值。

## 3. 天车卡片

### 3.1 卡面与数据来源

卡面顺序：名称 → X → Y → Z → `当前任务：源→目标` → `路权：[左端, 右端]` → 状态。
无任务或路权时对应显示“无”，状态为“空闲 / 已分配 / 执行中”。状态没有细分到下降、充磁、等待夹紧等动作步骤。

坐标取共享有效快照的 `XDisplay` / `YDisplay` / `ZDisplay`，最多保留三位小数。
读取失败时坐标显示为默认值 `0`，同时连接显示未连接、边框变红；此时的 `0` 不代表读到了现场零坐标。

### 3.2 悬浮框逐行布局

| 行 | 显示内容 | 含义 |
|---|---|---|
| 1 | `天车名称（状态）` | 天车名称与程序运行状态 |
| 2 | `连接：已连接/未连接    路权：[左端, 右端]/无` | 本轮缓存有效性及运行态记录的路权 |
| 3 | `X：…  Y：…  Z：…` | 三轴显示坐标 |
| 4（有任务） | `任务：…` | 搬运任务 `TaskId` 的前 8 位 |
| 5（有任务） | `源：设备名称（X=…）` | 源设备名称与配置位置，查不到设备时使用任务中的设备号和源 X |
| 6（有任务） | `目标：设备名称（X=…）` | 目标设备名称与配置位置，查不到设备时使用任务中的设备号和目标 X |
| 7（有任务且持有工件） | `板号：…  序号：…` | 天车当前持有工件的身份；界面此处标签为“板号” |
| 8（有任务且持有工件） | `直径：…  长度：…` | 当前持有工件的尺寸 |

无当前任务时只显示前 3 行。有任务但尚未持有工件时只显示前 6 行，工件资料取 `crane.CurrentWorkpiece`，不从任务表补取。
当前大屏没有绑定 `SignalText`，因此卡面和悬浮框都不展示有板、充磁、退磁、下压、回原点、接液盘及具体报警值。

### 3.3 路权展示同步

- 获取路权和设备预约成功时，记录整个搬运区间。
- 到达目标后，只有 `RightOfWayManager.Resize` 成功，才将 `Runtime.LockedInterval` 同步为 `[targetX−w/2, targetX+w/2]`。
- 卡面与悬浮详情在下次刷新时显示缩小后的区间；调整失败时保留原区间。
- 任务完成、回滚或异常清理后显示“无”。

## 4. 边框与外观

边框优先级：红 > 橙黄色 > 绿。设备和天车的判断条件不同。

| 颜色及资源 | 设备卡片 | 天车卡片 |
|---|---|---|
| 红 `StatusFaultBrush`，`#DC2626` | 采集失败、超时或断联（`!device.IsConnected`） | 状态读取失败，或 `HasAlarm == true` |
| 橙黄色 `StatusWaitingBrush`，`#D97706` | 已连接且被任务预约（`ResourceReservationManager.IsReserved`） | 读取成功、无报警且有当前任务 |
| 绿 `StatusIdleBrush`，`#16A34A` | 已连接且未预约 | 读取成功、无报警且无当前任务 |

设备内存“加工中”和 PLC 报警点位不单独改变设备边框，例如研磨机 `运行状态=2` 不会单独触发红框。
天车 `HasAlarm` 包含伺服报警、PLC 伺服报警和 PLC 报警任一非零；报警优先显示红框。

| 外观项目 | 当前设置（WPF 逻辑单位） |
|---|---|
| 设备/天车卡片 | 宽 300，边框 2，圆角 10，内边距 20，右侧与下侧间距各 12 |
| 顶部统计卡片 | 宽 220，灰色 `#E2E8F0` 边框，粗细 1 |
| 卡片背景 | 白色，无阴影 |
| 设备/天车名称 | 深色 `#0F172A`，字号 15，半粗体 |
| 类型/任务/路权 | 灰色 `#64748B`，字号 12 |
| 加工状态/天车状态 | 蓝色 `#2563EB`，半粗体；空闲也使用该色 |
| 坐标字体 | Consolas |

悬浮时弹出普通多行文本，没有额外卡片高亮、边框变色或固定展开控件；悬浮延时与展示时长沿用 WPF 默认行为。

## 5. 刷新与连接状态

- `ScreenViewModel` 构造时立即尝试刷新，随后由 `RuntimeTicker` 每 1s 尝试触发一次刷新；线路未启动或暂停不影响这条刷新路径。
- `ScreenViewModel` 构造后持续订阅节拍器，没有按页面是否可见停止刷新，切换到其他页面也不会取消该订阅。
- 设备后台采集持续运行，每轮并发读取各设备，统一替换快照后等待配置的 `DeviceIntervalMs`（默认 500ms）；大屏读取缓存，不在悬浮时另起采集。
- 天车由Application的CraneStateCollector每车独立采集、立即发布；大屏只查询GetFreshStatus，不直接发起通信。默认轮间等待500ms、快照最大年龄2000ms；未采集/失败/过期均按null交给卡片显示。UI秒级节拍与现场采集周期不同，节拍不保证数据严格每秒更新。
- 设备采集失败时写入断开、空快照，界面显示未连接、红框和“点位信号：无数据”；后续采集成功后恢复展示。天车读取失败时本轮状态按 `null` 展示。
- 首轮和定时触发共用整轮防重入入口：上一轮未结束时立即跳过本次触发，不等待、不排队，也不在结束后补跑。正常结束或异常时均释放占用标记，下一个节拍可以重新刷新。
- 防重入入口仍保留，但刷新正文只处理缓存与内存，不等待PLC。单车断电不拖延其他车的采集发布或页面更新；该车快照过期/失败会显示不可用。底层即时运动和动作确认仍走原通信机制。
- 刷新方法负责读取数据并给 ViewModel 属性赋值；属性变更通知和集合变更通知驱动 WPF 更新卡片及悬浮文本，不需要等下一个节拍。界面按注册表生成卡片，新增设备类型仍需相应驱动、点位表与名称映射支持。

## 6. 各设备悬浮点位（按实际显示顺序）

双头镗、研磨机、打号机和料架只读取点位表中的输入，下发参数和握手输出不在采集缓存中。
下表中的请求、到位、完成信号均以 `1` 表示成立、`0` 表示未成立，特殊值说明单独列出。

| 设备类型 | 顺序 | 中文点位名 | 英文键 | 值的含义 |
|---|---|---|---|---|
| 上/下料架 | 1 | 有料 | `HasMaterial` | 对应料架有板输入，1 有料、0 无料 |
| 双头镗 | 1 | 请求数据 | `RequestData` | 请求下发加工参数 |
| 双头镗 | 2 | 请求上料 | `RequestLoad` | 机床上料请求 |
| 双头镗 | 3 | 请求下料 | `RequestUnload` | 机床下料请求 |
| 研磨机 | 1 | 锁紧完成上料退出 | `LoadLockDone` | 锁紧完成，上料天车可退出 |
| 研磨机 | 2 | 加工中 | `Machining` | 0 加工完成、1 加工中 |
| 研磨机 | 3 | 请求数据 | `RequestData` | 请求下发加工参数 |
| 研磨机 | 4 | 请求上料 | `RequestLoad` | 机床上料请求 |
| 研磨机 | 5 | 请求下料 | `RequestUnload` | 机床下料请求 |
| 研磨机 | 6 | 运行状态 | `RunState` | 0 空闲、1 忙碌、2 机床报警，界面显示数字 |
| 研磨机 | 7 | 安全门 | `SafetyDoor` | 0 关闭、1 打开 |
| 研磨机 | 8 | 松开完成下料退出 | `UnloadReleaseDone` | 松开完成，下料天车可退出 |
| 打号机 | 1 | 忙碌 | `Busy` | 0 空闲、1 忙碌 |
| 打号机 | 2 | 有新打印内容 | `NewPrintContent` | 0 无新内容、1 有新内容 |
| 打号机 | 3 | 加工完成 | `ProcessDone` | 0 未完成、1 完成 |
| 打号机 | 4 | 运行中 | `Running` | 0 停止、1 运行 |

斜床采用 FOCAS：读取机床输入 `#1001～#1005`，并读回上位机握手输出 `#1101～#1105`；加工参数宏只写不读。大屏只展示，不提供写入操作。

| 顺序 | 中文点位名 | 英文键 | 宏变量 | 信号方向 |
|---|---|---|---|---|
| 1 | 天车上料完成 | `CraneLoadDone` | #1103 | 上位机 → 机床，读回值 |
| 2 | 天车上料到位 | `CraneLoadInPlace` | #1102 | 上位机 → 机床，读回值 |
| 3 | 天车下料完成 | `CraneUnloadDone` | #1105 | 上位机 → 机床，读回值 |
| 4 | 天车下料到位 | `CraneUnloadInPlace` | #1104 | 上位机 → 机床，读回值 |
| 5 | 数据下发完成 | `DataSentDone` | #1101 | 上位机 → 机床，读回值 |
| 6 | 请求数据 | `RequestData` | #1001 | 机床 → 上位机 |
| 7 | 请求上料 | `RequestLoad` | #1002 | 机床 → 上位机 |
| 8 | 请求下料 | `RequestUnload` | #1004 | 机床 → 上位机 |
| 9 | 尾座夹紧到位 | `TailstockClamped` | #1003 | 机床 → 上位机 |
| 10 | 尾座分开到位 | `TailstockOpened` | #1005 | 机床 → 上位机 |

点位含义对应《设备寄存器地址》目录中的各设备协议文档。
当前 `DriverFactory` 没有货叉、动平衡机、验点机的真实驱动；已装载的这类设备可以生成卡片，但无法通过当前驱动取得实时点位。
