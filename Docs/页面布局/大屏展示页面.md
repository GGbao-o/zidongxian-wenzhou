# 大屏展示页面（只读）

> 展示现场信号与内存数据，不提供控制按钮。本文以当前 `ScreenPageView` / `ScreenViewModel` 实现为准，更新于 2026-10-16。

## 1. 页面布局与顶部统计

页面从上到下依次是标题与说明、两个应用服务统计卡片、设备卡片组、天车卡片组。
设备先按内置`ProcessRoute`工艺顺序排序：上料架 → 双头镗 → 斜床 → 研磨机 → 动平衡机 → 打号机 → 验点机 → 下料架。同一类型有多台时全部集中展示，类型内部按设备ID升序；没有设备的工序不留空位，未纳入路线的设备类型放在末尾并按ID排列。该规则只改变展示顺序，不改变实际工艺路线或调度。天车仍按序号排序；设备固定两行、天车单行，超出可视区域时通过横向滚动查看，页面内容较高时可纵向滚动。
卡片来自注册表，`ConfigurationLoader` 只装载数据库启用的设备与天车。

| 顶部卡片 | 数量来源 | 悬浮框每行内容 |
|---|---|---|
| 候选任务（TransportTaskGenerator） | 当前候选任务池数量 | `版号/序号  源设备→目标设备  优先级数字` |
| 已派发任务（集中调度） | `Runtime.CurrentTask != null` 的天车数量 | `天车名称  版号/序号  源设备→目标设备  天车状态` |

没有内容时分别显示“无候选任务”“无已派发任务”。已派发详情中的工件查不到时显示 `?`。
已派发数量统计已进入天车当前运行态的任务，不包括尚在 Worker 通道等待取出的任务。

## 2. 设备卡片

设备区使用`UniformGrid Rows="2"`固定为两行，卡片仍为原有宽度；内容超出视口时横向滚动。天车区保持原有单行布局。

### 2.1 卡面与数据来源

卡面从上到下显示名称/连接、类型/工件存在状态、工件身份、长度/直径、可选PLC状态、设备类型对应的信号标签、预约归属。

- **工件存在状态**：显示“有工件/无工件”；上料架有可用队头时为“队头有工件”。不以工件引用推断PLC正在加工。
- **工件身份**：上料架显示“队头工件”，优先取位置Queue、状态Waiting且QueueOrder最小的任务，未传入队头时按通用行模型回退device.CurrentWorkpiece；其他设备显示“内存工件”，取device.CurrentWorkpiece。卡面和悬浮框使用同一份工件资料。
- **PLC状态**：研磨机读取Machining，1为加工中、0为加工完成；打号机ProcessDone=1显示加工完成，否则根据Busy显示忙碌/空闲。缺失反馈显示未知。双头镗、斜床和料架未提供独立加工反馈，不显示这行，也不从请求信号推算加工状态。
- **预约归属**：本轮ResourceReservationManager.Snapshot的设备号→TaskId，与天车当前任务关联得到天车名称。未预约显示未预约；已预约但暂未关联到车显示“已预约（归属暂不可用）”。预约判断与调度逻辑不变。

| 设备 | 卡面关键信号 |
|---|---|
| 上料架 | 允许取料：HasMaterial同向 |
| 下料架 | 允许放料：对缓存HasMaterial再次反转，未知仍为未知 |
| 双头镗/斜床 | 请求数据、请求上料、请求下料 |
| 研磨机 | 加工中、请求数据、请求上料、请求下料 |
| 打号机 | 忙碌、加工完成、运行中 |
| 其他未接入类型 | 不虚构点位，卡面无信号标签 |

信号标签由CardSignal提供：`● 1`表示成立、`○ 0`表示未成立、`未知`表示没有可用值。设备快照断开、Quality不良、点名缺失、值为null或非布尔类型时，关键信号保持未知，不使用SignalSnapshot.GetBool的缺失返回false作为展示依据。所有展示都读取现有缓存，不增加通信。

| 主要绑定字段 | 展示含义 |
|---|---|
| ConnectionText | 连接状态，仍按device.IsConnected判断；Quality不良只使信号不可用，不另外改边框策略 |
| WorkpieceStateText / WorkpieceCaptionText | 有工件/无工件/队头有工件，以及“内存工件”或“队头工件”的版号/序号 |
| DimensionsText | 长度/直径，最多三位小数；无工件为“—” |
| HasMachiningStatus / MachiningText | 控制PLC状态行是否显示，及其真实反馈文本 |
| KeySignals | 对应机型的CardSignal列表，自动换行，不读PLC |
| ReservationText | 预约天车名称或明确的未预约/归属暂不可用 |

卡片示例（示意数据）：

```text
双头镗01                     已连接
双头镗 · 有工件
内存工件：A261014001/1
长度：1200.1  直径：180.3
请求数据 ● 1  请求上料 ○ 0  请求下料 ○ 0
预约：天车02
```

### 2.2 悬浮框逐行布局

| 行 | 内容 |
|---|---|
| 1 | 设备名称（类型） |
| 2 | 连接状态、工件存在状态；有明确加工反馈的设备追加PLC状态 |
| 3 | 预约天车名称、未预约或归属暂不可用 |
| 4 | 当前工件：无，或资料标题 |
| 有工件时随后两行 | 版号/序号；长度/直径 |
| 随后 | 点位信号标题及全部缓存点位，按英文键排序，一点一行 |

布尔值显示1/0，null显示未知，浮点最多三位小数。断开或质量不良时不把残留缓存点位当成有效现场值。完整点位表见第6节。

## 3. 天车卡片

### 3.1 卡面与数据来源

卡面顺序：名称/执行状态标签 → 连接状态 → 源到目标任务 → 任务工件身份 → 长度/直径 → 当前阶段 → 单行XYZ → 路权 → 内存持板 → 有板/充磁/退磁/报警标签。

任务工件优先按Runtime.CurrentTask.WorkpieceRuntimeId查RuntimeTaskManager，找不到时回退天车持有引用；所以尚未取料也能显示本次任务工件。无可查工件且无任务时显示无，已有任务但资料不可用时明确显示信息不可用。内存持板只看crane.CurrentWorkpiece，X11有板只看共享快照，两者分开呈现，不做额外一致性联锁。

阶段读取CraneRuntime.CurrentStep，是Application最近发布的执行步骤说明。RunFlowAsync入口初始化，TransferContext.LogStep在原有步骤日志时发布，充磁前有板检查在每轮等待前发布次数；不读取日志文件，不由坐标或信号猜动作。该字段仅供展示，不参与调度/取消/成功失败判断；CurrentTask清空时同时清除阶段，后续收尾日志不会重新写入。无任务显示无任务，有任务尚无步骤显示已分配、等待执行。

XYZ仍取共享有效快照的显示值，最多三位小数，压为一行。快照未采集、失败、过期等不可用时，卡面和悬浮坐标显示`—`，不显示伪零坐标。连接状态为未连接可能表示缓存不可用。单个X点读取失败时，其标签显示未知；其余有效点保持显示。

| 主要绑定字段 | 展示含义 |
|---|---|
| TaskText | 源设备→目标设备名称，无任务为无 |
| WorkpieceText / DimensionsText | 任务关联工件身份及尺寸，取料前即可显示 |
| StageText | Application最近发布的步骤；不是进度百分比，也不保证每个短暂步骤都被1s节拍显示 |
| CoordinateText | XYZ显示坐标的单行文本，无有效快照为“—” |
| RightOfWayText | Runtime.LockedInterval，非预测区间 |
| HoldingText | 内存持板引用是否存在，独立于X11现场有板信号 |
| KeySignals | 有板、充磁、退磁、报警四个三态标签 |

卡片示例（示意数据；尚未完成取料也能显示任务工件）：

```text
天车02                         执行中
已连接
任务：上料架→双头镗01
任务工件：A261014001/1
长度：1200.1  直径：180.3
阶段：取料：第1次检查有板（补降0/3次）
X：4800  Y：200  Z：400
路权：[4800, 18200]
内存持板：无
有板 ● 1  充磁 ○ 0  退磁 ● 1  报警 ○ 0
```

### 3.2 悬浮详情

公共部分依次显示：名称/执行状态、连接/路权、XYZ、阶段、内存持板、点位信号。点位明细包含显示坐标、编码器坐标、回原点、三个具体报警值、有板/充退磁/下压、接液盘及物理原点；单个未知布尔值用`—`表示，整份快照不可用显示无数据。

有当前任务时，公共部分后追加任务短号（TaskId前8位）、源名称/配置X、目标名称/配置X，以及任务工件的版号/序号/直径/长度。无当前任务也能查看完整有效信号明细。

### 3.3 路权展示同步

- 获取路权和设备预约成功时，记录整个搬运区间。
- 到达目标后，只有 `RightOfWayManager.Resize` 成功，才将 `Runtime.LockedInterval` 同步为 `[targetX−w/2, targetX+w/2]`。
- 卡面与悬浮详情在下次刷新时显示缩小后的区间；调整失败时保留原区间。
- 任务完成、回滚或异常清理后显示“无”。

## 4. 边框与外观

边框优先级：红 > 橙黄色 > 绿。设备和天车的判断条件不同。

| 颜色及资源 | 设备卡片 | 天车卡片 |
|---|---|---|
| 红 `StatusFaultBrush`，`#DC2626` | 采集失败、超时或断联（`!device.IsConnected`） | 有效状态不可用，或 `HasAlarm == true` |
| 橙黄色 `StatusWaitingBrush`，`#D97706` | 已连接且被任务预约（`ResourceReservationManager.IsReserved`） | 读取成功、无报警且有当前任务 |
| 绿 `StatusIdleBrush`，`#16A34A` | 已连接且未预约 | 读取成功、无报警且无当前任务 |

设备工件存在状态、PLC加工状态和PLC报警点位不单独改变设备边框，例如研磨机 `运行状态=2` 不会单独触发红框。
天车 `HasAlarm` 包含伺服报警、PLC 伺服报警和 PLC 报警任一非零；报警优先显示红框。

## 5. 刷新与连接状态

- `ScreenViewModel` 构造时立即尝试刷新，随后由 `RuntimeTicker` 每 1s 尝试触发一次刷新；线路未启动或暂停不影响这条刷新路径。
- `ScreenViewModel` 构造后持续订阅节拍器，没有按页面是否可见停止刷新，切换到其他页面也不会取消该订阅。
- 设备后台采集持续运行，每轮并发读取各设备，统一替换快照后等待配置的 `DeviceIntervalMs`（默认 500ms）；大屏读取缓存，不在悬浮时另起采集。
- 天车由Application的CraneStateCollector每车独立采集、立即发布；大屏只查询GetFreshStatus，不直接发起通信。默认轮间等待500ms、快照最大年龄2000ms；未采集/失败/过期均按null交给卡片显示。UI秒级节拍与现场采集周期不同，节拍不保证数据严格每秒更新。
- 设备采集失败时写入断开、空快照，界面显示未连接、红框和“点位信号：无数据”；后续采集成功后恢复展示。天车读取失败时本轮状态按 `null` 展示。
- 首轮和定时触发共用整轮防重入入口：上一轮未结束时立即跳过本次触发，不等待、不排队，也不在结束后补跑。正常结束或异常时均释放占用标记，下一个节拍可以重新刷新。
- 防重入入口仍保留，但刷新正文只处理缓存与内存，不等待PLC。单车断电不拖延其他车的采集发布或页面更新；该车快照过期/失败会显示不可用。底层即时运动和动作确认仍走原通信机制。
- 刷新方法负责读取数据并给 ViewModel 属性赋值；属性变更通知和集合变更通知驱动 WPF 更新卡片及悬浮文本，不需要等下一个节拍。界面按注册表生成卡片，新增设备类型仍需相应驱动、点位表与名称映射支持。

采集缓存改变不直接通知本页绑定；上面的“不需要等下一个节拍”指刷新方法已给绑定属性赋值后的WPF更新。后台采集完成到页面取值仍需等待本页下一次刷新，调快采集不会把UI1s节拍变快。手动页有自己的绑定属性和节拍订阅，仅复用同一个CraneStateStore。
