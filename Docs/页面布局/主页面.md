# 主页面

源码：[MainPageView.xaml](../../src/AutomatedLine.Ui/Views/MainPageView.xaml)、[MainViewModel](../../src/AutomatedLine.Ui/ViewModels/MainViewModel.cs)、[WorkpieceTaskViewModel](../../src/AutomatedLine.Ui/ViewModels/WorkpieceTaskViewModel.cs)。核对日期：2026-10-13。

## 1. 页面结构与概览

顶部四张等宽概览卡展示线路状态、工件任务总数、已装载设备数、已装载天车数；下方任务列表卡的右上角有线路启动/暂停、ERP监听切换与添加任务，按钮下方显示ERP接收状态，卡内表格支持横向/纵向滚动。

程序启动默认持续监听ERP，按钮显示“暂停 ERP 监听”；点击暂停后续批次，再点“监听 ERP 工件”继续，当前批次仍完成入队与文件清理。默认D:\job1\job1.txt，可在参数页“ERP接收”编辑路径/间隔/编码。合法工件按文件从上到下自动启动为Waiting，分配递增QueueOrder并追加已有队尾，不按业务序号排序；无需逐件点击“启动”。不改变整条线路状态；成功行删除、错误或重复行保留。监听不因切换页面停止，具体格式及日志见[ERP文件接收说明](../ERP文件接收说明.md)。

设备/车数量来自运行注册表，仅包括装载的启用配置；工件数包括所有仍在列表中的状态。线路状态支持未启动、启动中、自动运行、请求暂停、已暂停、故障暂停文案，但当前 LineControlService 直接使用未启动/运行/暂停/故障暂停，不经过两个中间状态。

线路状态大字30号加粗：未启动为灰#64748B，自动运行/启动中蓝#2563EB，已暂停/请求暂停橙#D97706，故障暂停红#DC2626。颜色作用于状态文字，不改变概览卡边框。卡下的“候选周期”来自构造时读取的GenerateIntervalMs，不是实时测得调度耗时。

## 2. 线路启动/暂停

| 当前状态 | 按钮 | 调用效果 |
|---|---|---|
| Running | 暂停线路 | Pause 置 Paused，停止后续生成/派发/领取新任务 |
| Stopped、Paused、PausedByFault | 启动线路 | 先做冷启动核对，再 Start 置 Running |

ViewModel也为保留状态Starting映射“暂停线路”，但当前服务不进入该状态；ToggleLine实际按IsRunning判断分支。

冷启动核对只有告警，不阻止启动；天车部分并发有界等待有效且X11已知的共享快照，最多通信超时配置，未取得时记录该车核对未完成而非判为无板。不装载配置、不重建Worker、不恢复旧进程工件。暂停后设备/天车采集与页面刷新继续，候选池由生成器清空。

该核对在程序打开时也执行一次，并非只在进程首次打开或内存任务完全为空时执行。每次点击“启动线路”都会先核对：设备HasMaterial=true/天车X11=true但该资源CurrentWorkpiece为空时，新增Warning活动报警并写日志，不弹Error错误框；提示“将不参与调度”没有禁用该车的代码。其业务影响是提醒人工及可能等待有效缓存，结束后仍调用Start，残留板本身不会凭信号生成工件任务。

已执行的当前搬运继续，不因为这个按钮取消或 PLC 急停；某车故障暂停时其他在途车也继续当前流程。尚在车通道里的 Assigned 任务等待恢复运行后领取。

若Worker已出队，但RunFlowAsync入口此时读到线路未运行，则在取路权/预约及任何PLC动作前回滚分配：工件Assigned回Waiting，源/目标设备引用、信号、工件位置/工序/排位保留，天车当前任务/路权显示清空并回Idle，不弃板、不新增报警、不把普通暂停升级故障。已接受的人工中止与宿主取消仍走原异常处理。

候选池到生成器下一轮才清空；调度进入本轮后不在每个派发点重复检查，暂停本身不清CraneTaskChannels。入口补查和volatile状态读写减少未开始任务越过暂停的窗口，但不是全线原子停发，也不影响已通过入口的当前流程。

需要弃掉某台车当前执行的搬运时，在[手动操作页](手动操作页面.md#7-中止当前任务)选择该车并点击“中止当前任务”。该操作统一弃板并故障暂停，只取消该车本次流程，现场负责停止天车；这里的线路暂停或工件暂停按钮不承担此作用。

## 3. 工件表各列

| 列 | 来源与含义 |
|---|---|
| 板号/序号 | WorkpieceInfo 身份；与内存 GUID 不同 |
| 直径/长度 | 工件尺寸，参与设备能力匹配和运动目标计算 |
| 堵厚 | WorkpieceInfo.PlugThickness原始录入值；双头镗309按整数Word下发 |
| 堵孔 | 70 小孔、100 大孔；也参与斜床偏移、研磨模式及打号机内径 |
| 打印内容 | 打号机 UTF-8 写入内容 |
| 斜床工艺 | LatheMachiningMode，录入范围 1～10，写宏 #909 |
| 当前工序 | Runtime.CurrentProcess，放料成功后更新 |
| 入线顺序 | 当前 Queue+Waiting 工件的连续排位，其他为 - |
| 当前位置 | Runtime.CurrentLocation 文本：队列、设备、天车、已丢弃 |
| 下一道工序 | 已启动按自身锁定工艺；Created仅预览最新模板，首次启动才锁定 |
| 下一道工序位置 | 该工序启用设备 X，多个以逗号分隔；不表示已经预约或选定目标 |
| 状态 | 未启动、排队中、已派发、执行中、已完成、已丢弃、已暂停 |
| 操作 | 编辑、启动、暂停、删除，按状态可用 |

“排队中”是 Waiting 的显示文本，即使工件目前已在设备上也显示这项；判断真实内存位置应同时看当前位置。

## 4. 入线顺序和队头

人工添加只创建Created，位置Queue，不占待上料排位；人工启动分配递增Runtime.QueueOrder，置Waiting。ERP文件接收在同一批提交内按原行序自动完成启动和入队，直接参与排位；UI为Queue+Waiting现算1、2、3…连续排位，ERP与人工启动共用顺序号。

暂停以 CAS 将 Waiting 改 Paused，只有成功才清 QueueOrder，后面排位补齐。若调度已先将工件改 Assigned，暂停失败且保留排位。再次启动重新分配序号，如果工件仍在 Queue 则排到队尾。只有当前队头可生成上料架来源候选。

派发改 Assigned 后就退出 UI 排位，后面补位；这发生在物理取料前。充磁前异常回 Waiting 并保留原序号，仍在 Queue 的工件可以重新回到原先相对位置。

设备上的 Waiting 工件暂停后，位置、工序和设备引用均保留；重新启动继续从该设备生成下一段搬运，不把板退回上料架。

## 5. 行内按钮

| 按钮 | 可用状态 | 实际动作 |
|---|---|---|
| 编辑 | Created | 开工件编辑弹窗；保留 RuntimeId，整体替换 Info；板号、序号只读 |
| 启动 | Created、Paused | Created首次锁定最新工艺，Paused沿用原工艺；改Waiting、分配新QueueOrder，位置/工序保持 |
| 暂停 | Waiting | 改 Paused，清 QueueOrder；不取消正在执行的任务 |
| 删除 | Created、Waiting、Paused、Discarded、Completed | 清设备/车上身份一致的工件引用，然后从内存任务列表移除 |

Assigned/Running 不开放这些行内修改按钮。Start/Pause/TryUpdate 在 RuntimeTaskManager 还会检查当前状态；删除入口检查行 CanClear 后调用 Remove，Remove 本身没有再按状态校验。

工序页勾选只影响之后首次启动的任务；ERP同批自动入队共用一版新工艺。已启动、设备上、暂停恢复及故障回滚保留原工艺。必做设备后来不可用时不跳过，该工序无启用设备则位置显示“无启用设备，等待”。缺少原快照显示“工艺异常，等待处理”；首次启动缺少固定上下料设备时弹“工件无法启动”，保持Created且不占排位。

删除不是新增一个“Deleted”枚举值，也不是改 Discarded；不会删除设备配置、清设备信号快照、写 PLC、移走实物或自动清路权/预约/车通道。设备若原来引用该工件，引用会清空，卡片内存加工状态随之变化。

## 6. 添加与编辑弹窗

新增与编辑共用八个输入：板号、序号、直径、长度、堵厚、堵孔、打印内容、斜床工艺。板号不能为空，序号须非负整数（>=0，允许0，与ERP接收一致），直径/长度须正数，堵孔限定 70/100，斜床工艺整数 1～10。其余字段没有额外工艺范围校验；人工新增的板号/序号没有列表唯一性校验，ERP入口仍按版号和序号去重。

直径、长度、堵厚输入框绑定原始文本，逐字输入时保留小数点及尾零，例如`120.`、`120.50`，仅点击“确定”时按当前区域设置统一解析。三项必须为有限数值，直径/长度另须大于0；空白、错误文本、NaN/无穷大或数值溢出不允许提交，不使用旧值或默认为0。堵厚不新增正负范围限制。编辑按当前区域回填小数并沿用原工件身份；确认后WorkpieceInfo仍保存double，PLC倍率及舍入不变。

编辑仅允许Created；Paused也不能编辑，ERP导入任务已自动启动也不开放编辑。弹窗关闭确认时TryUpdate再查状态，防止打开弹窗期间任务已启动。修改保留任务GUID，前后参数写operation日志，统一记录堵厚。界面长度/直径/堵厚仍保存double原值；双头镗下发时长度与堵厚舍入为整数，外径×10表达一位小数，不回写页面原值。

## 7. 异常在主页面如何显示

取料充磁调用后异常：该行保留，状态和位置显示已丢弃，不再生成候选；允许人工删除记录。主页面没有异常原因、阶段或最后步骤专用列，具体内容在报警页、错误弹窗与日志查看。

充磁调用前异常：工件回 Waiting，位置仍为原队列/设备，显示排队中；线路显示故障暂停。它没有被标为 Discarded，现场处理后启动线路可再派发。

取料X11原位无板不会立即报错，会按配置仅Z补降并重查，默认追加3次×5mm；补降耗尽仍无板、读取/运动失败均发生在充磁前，工件保留。每次补降位置、次数、累计指令距离看statemachine日志，最终耗尽的错误详情也包含最后已读坐标；主页面不增加这些过程列。

人工中止当前天车任务始终按弃板显示，不受充磁前保留策略影响。异常窗口标题、内容及现场处理提示见[报警处理页面](报警处理页面.md#21-异常弹窗固定格式)；关闭窗口不会恢复线路或删除这行工件记录。

## 8. 刷新与外观

任务结构和启动/暂停变化通过 RuntimeTaskManager.Changed 更新；状态机进度由 RuntimeTicker 每 1s 就地刷新。任务身份或数量变化才重建行，通常保留选中和滚动位置。

ERP文件一次整批读取/解析，通过TryAddImportedBatch一次提交创建并按行序自动启动入队，只发一次Changed；几十行不会逐件同步清空重建列表。主页面保持现有刷新方法，未引入行复用或额外异步刷新队列，文件接收的去重及成功行清理规则不变。

概览数量随节拍更新，线路状态由 StateChanged 通知；任务表采用只读数据列加行内操作按钮。公共白色卡片、灰色边线等样式见[页面索引](README.md)，没有为工件异常行使用大屏卡片式路权边框。
