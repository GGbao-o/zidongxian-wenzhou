# 报警处理页面

源码：[AlarmPageView.xaml](../../src/AutomatedLine.Ui/Views/AlarmPageView.xaml)、[AlarmViewModel](../../src/AutomatedLine.Ui/ViewModels/AlarmViewModel.cs)、[ActiveAlarmStore](../../src/AutomatedLine.Application/Alarms/ActiveAlarmStore.cs)、[AlarmManager](../../src/AutomatedLine.Application/Alarms/AlarmManager.cs)。核对日期：2026-10-11。

## 1. 页面和每列

页面包含标题、清除报警列表按钮、活动报警表与操作提示。

| 列 | 显示含义 |
|---|---|
| 时间 | 最近发生 LastAt，MM-dd HH:mm:ss |
| 级别 | 提示、警告、错误、严重 |
| 来源 | 发出报警的业务来源 |
| 内容 | 原因详情；状态机异常含路线、阶段、原因及取料充磁标记；前序步骤查看日志 |
| 系统动作 | 程序已采取动作/现场处理提示，没有值为 - |
| 次数 | 同等级、来源、内容重复发生后的合并次数 |
| 资源 | 天车N、设备N；无关联资源为 - |

活动列表只在本进程内保留；历史可查 Logs/日期/alarm.txt。

## 2. 合并、刷新和弹窗

合并键为等级+来源+内容，不包含资源号；新项插入前面，重复项更新时间/次数，但不会因为重复自动移动到列表首位。Changed 事件触发 UI 重建，非每秒轮询；重建可能改变当前选择。

每次 Raise 都写日志并发事件。App 对 Error/Critical 弹错误框，含来源、系统动作、时间和内容；Warning 记录在列表/日志，不弹同样的错误框。弹框关闭不清报警、不启动线路。

### 2.1 异常弹窗固定格式

实际入口为 [App.xaml.cs](../../src/AutomatedLine.Ui/App.xaml.cs) 的 `AlarmManager.Raised` 订阅。使用系统 `System.Windows.MessageBox`，不使用参数编辑的自定义 XAML 窗口；标题固定为“线路异常（已暂停）”，错误图标，只有“确定”按钮。

正文按以下格式拼接，内容后有一个空行；来源与资源写在同一行：

```text
{alarm.Message}

来源：{alarm.Source}  {天车ID或设备ID；未关联时为空}
系统动作：{alarm.SystemAction}
时间：{alarm.LastAt:yyyy-MM-dd HH:mm:ss}
```

资源使用数字 Id，例如“天车1”，不使用排序号 No。正文没有独立的等级、重复次数或堆栈栏；`SystemAction=null` 时此行为空，报警列表则显示“-”。标题是固定文字，弹窗自身不检查或修改线路状态；搬运故障由协调器先进入故障暂停再发报警。

事件经 `Dispatcher.Invoke` 同步切到 UI 线程显示模态窗口，发出报警的调用要等窗口关闭后才返回；这不停止其他天车已开始的搬运。活动列表的重复合并不会抑制 `Raised`，同内容 Error 再次发出仍会弹框。Warning/Info 不弹此框。

### 2.2 状态机异常正文

[CraneStateMachine.BuildFailure](../../src/AutomatedLine.Application/Workers/CraneStateMachine.cs) 生成：

```text
[{天车名称}] 任务 {板号}/{序号} {源设备名称}→{目标设备名称} 步骤[{阶段}] 异常：{原因}{边界说明}
```

工件和资源查找完成后，路线包含板号/序号及设备名称；初始化失败时可能仅有“设备1→设备2”。“任务”后不是搬运 GUID，尺寸、完整任务 Id、最后一条步骤日志和堆栈未单独显示。阶段有初始化、获取资源、审核源(名称)、设置速度、取料(名称)、中转(源→目标)、放料(名称)、收尾；阶段并不细分成取料中的每次下降或充磁动作，具体失败操作由原因和日志说明。

| 情况 | 原因 | 正文末尾固定说明 | 系统动作 |
|---|---|---|---|
| 普通故障，取料充磁调用前 | `ex.Message` | （取料充磁未开始：工件保留在原位置） | 保留工件提示 |
| 普通故障，取料充磁调用开始后 | `ex.Message` | （取料充磁已开始：板可能在天车上） | 弃板提示 |
| 人工中止 | 人工中止当前任务 | （人工中止：工件丢弃） | 弃板提示，不区分是否充磁 |
| 人工中止与动作异常同时发生 | 人工中止当前任务；`ex.Message` | （人工中止：工件丢弃） | 弃板提示 |
| 宿主停止引发执行令牌取消 | 任务被取消 | 按取料充磁边界选择普通故障说明 | 按边界保留或弃板 |

[TaskAbortCoordinator](../../src/AutomatedLine.Application/Alarms/TaskAbortCoordinator.cs) 当前系统动作原文：

**保留工件：**

```text
尚未开始取料充磁，已释放路权/预约/锁；线路已暂停 工件置保留，PLC信号正确 天车在安全位置后重新启动线路可再次搬运
```

**弃板：**

```text
已释放路权/预约/锁并标记该工件为已丢弃，线路暂停；现场残留工件取走 确保天车在安全位置后重新启动即可
```

这些文字说明内存处理结果和现场操作条件，协调器本身不自动回安全位、取走实物或复位 PLC 点位。

### 2.3 Worker 兜底与启动错误

Worker 仅在天车仍挂着 CurrentTask 时调用兜底 Abort，正文为“[天车名称] 兜底异常：原因”，没有完整路线/阶段。原因可能是“任务被取消（兜底）”“人工中止当前任务（兜底）”或 `ex.Message`，系统动作使用弃板提示。状态机正常完成清理后 CurrentTask 已为空，Worker 不再重复发这条兜底报警。

程序最初装载配置失败会 Raise 系统 Error，内容为“配置装载失败：原因”，系统动作为“界面继续启动；请检查 appsettings.json 的连接串与数据库可用性”。该调用发生在弹窗订阅之前，因此写活动列表及日志，后续订阅不会补弹。

冷启动残留板使用 Warning，只写列表/日志；冷启动天车缓存等待超时只记 system 警告日志。后台采集失败不调用此 Error 弹窗入口；手动 PLC 命令返回失败通常写手动页底部 Message，只有人工中止的自动搬运清理另走上述异常报警。

## 3. 清除按钮的边界

“清除报警列表”仅 ActiveAlarmStore.Clear，磁盘日志保留。它不写天车 D4514、不清 PLC 报警，不回安全位、不释放额外资源、不删工件，也不将 PausedByFault 改 Running。

清 PLC 报警在手动页操作；现场取板/车回安全位置等按现场流程完成，再到主页面启动线路。

## 4. 异常工件与提示文字

取料充磁调用前异常记录“保留工件”的动作，工件回 Waiting；调用开始后异常记录弃板动作，主页面仍可见 Discarded 记录。详细原因以实际报警内容为准。

页面默认提示“异常由程序自动清理，无需人工干预”指程序内存清理，不表示现场无需处理实物；TaskAbortCoordinator 的实际实现没有物理回位和 PLC 握手复位。页面没有额外人工清内存、补工件、释放锁或断点续跑按钮。
