# 报警处理页面

源码：[AlarmPageView.xaml](../../src/AutomatedLine.Ui/Views/AlarmPageView.xaml)、[AlarmViewModel](../../src/AutomatedLine.Ui/ViewModels/AlarmViewModel.cs)、[ActiveAlarmStore](../../src/AutomatedLine.Application/Alarms/ActiveAlarmStore.cs)、[AlarmManager](../../src/AutomatedLine.Application/Alarms/AlarmManager.cs)。核对日期：2026-10-08。

## 1. 页面和每列

页面包含标题、清除报警列表按钮、活动报警表与操作提示。

| 列 | 显示含义 |
|---|---|
| 时间 | 最近发生 LastAt，MM-dd HH:mm:ss |
| 级别 | 提示、警告、错误、严重 |
| 来源 | 发出报警的业务来源 |
| 内容 | 原因详情；状态机异常含路线、阶段、原因及取料充磁标记；前序步骤查看日志 |
| 系统动作 | 程序已采取动作/现场处理提示，没有值为 - |
| 次数 | 同等级、来源、内容重复发生后的合并次数 |
| 资源 | 天车N、设备N；无关联资源为 - |

活动列表只在本进程内保留；历史可查 Logs/日期/alarm.txt。

## 2. 合并、刷新和弹窗

合并键为等级+来源+内容，不包含资源号；新项插入前面，重复项更新时间/次数，但不会因为重复自动移动到列表首位。Changed 事件触发 UI 重建，非每秒轮询；重建可能改变当前选择。

每次 Raise 都写日志并发事件。App 对 Error/Critical 弹错误框，含来源、系统动作、时间和内容；Warning 记录在列表/日志，不弹同样的错误框。弹框关闭不清报警、不启动线路。

## 3. 清除按钮的边界

“清除报警列表”仅 ActiveAlarmStore.Clear，磁盘日志保留。它不写天车 D4514、不清 PLC 报警，不回安全位、不释放额外资源、不删工件，也不将 PausedByFault 改 Running。

清 PLC 报警在手动页操作；现场取板/车回安全位置等按现场流程完成，再到主页面启动线路。

## 4. 异常工件与提示文字

取料充磁调用前异常记录“保留工件”的动作，工件回 Waiting；调用开始后异常记录弃板动作，主页面仍可见 Discarded 记录。详细原因以实际报警内容为准。

页面默认提示“异常由程序自动清理，无需人工干预”指程序内存清理，不表示现场无需处理实物；TaskAbortCoordinator 的实际实现没有物理回位和 PLC 握手复位。页面没有额外人工清内存、补工件、释放锁或断点续跑按钮。
