# 工序展示页面

源码：[ProcessPageView.xaml](../../src/AutomatedLine.Ui/Views/ProcessPageView.xaml)、[ProcessViewModel](../../src/AutomatedLine.Ui/ViewModels/ProcessViewModel.cs)、[ProcessPlanService](../../src/AutomatedLine.Application/Routing/ProcessPlanService.cs)。核对日期：2026-10-19。

## 1. 布局和列

页面标题为“新工件工艺设置”，上方显示完整中文路线。工序表仍固定八行：上料、双头镗、斜床、研磨、动平衡、打号、验点、下料，顺序不能改。

| 列 | 含义 |
|---|---|
| 顺序 | 固定路线的先后顺序，不可拖动修改 |
| 工序 | ProcessType 的中文文本 |
| 启用 | 工序后的小勾选框，选中参与、取消跳过；上料和下料固定勾选 |
| 设备类型 | 对应 DeviceType |
| 工序状态 | 固定工序、缺少设备无法启动、新工件参与/跳过、无设备跳过、尚未实现不可启用 |
| 设备数量 | 运行注册表中的对应启用设备数 |

## 2. 判定与刷新

有启用设备且已实现执行策略的加工工序默认勾选，保存过的取消状态继续保留。离线、报警、占用或预约不自动取消勾选；无设备的加工工序灰显且不参与新路线。上料和下料固定保留，缺少启用设备时禁止首次启动。

每 1s 仅刷新显示，不触发保存或提示。Forking虽有枚举但不在八行中；动平衡/验点尚无驱动及取放策略，灰显且不能勾选，不能仅凭数据库中启用设备就进入生产路线。

## 3. 保存、弹窗与生效范围

每次用户勾选或取消都会保存运行目录`appsettings.json`的`App.processPlan.enabledProcesses`，保存后立即同步重载。成功弹出“工艺已更新”，列出当前完整路线，例如：

```text
当前最新工艺路线：

上料 → 斜床 → 研磨 → 打号 → 下料

仅对之后首次启动的工件生效；ERP任务在自动入队时生效。
已经启动或在设备上的工件继续使用原工艺。
```

保存失败恢复原勾选并弹出“工艺未更新”，不发布成功提示。修改其他普通参数时保留已保存的工艺节点，避免旧参数窗口覆盖新勾选。

人工Created任务在首次点击“启动”时才锁定最新完整路线；ERP整批自动入队时只捕获一次，同批使用同一份不可变快照。已启动、设备上、暂停恢复及故障回滚的工件不更新工艺。必做设备之后离线、停用或移除时保留该工序并等待，不按新勾选跳过，也不判完成。主页面下一工序和生成器均按工件自己的快照计算。

模板持久化到JSON；工件及其快照仍只在内存，程序重启不恢复旧工件。此页不写PLC，也不展示工件加工进度百分比。
